# Replica 실행 완료 기준

## 목적

Replica의 목표는 원제품 전체를 다시 만드는 것이 아니다. 공개 자료에서 확인한
고객 대상 AI 기능을 공개된 오픈소스, API, 데이터와 일반적인 코드로 실제 구현하고,
비슷한 입력에서 비슷한 종류의 최종 산출물이 나오는지 보여주는 것이다.

완료 결과는 다음 문장을 뒷받침할 수 있어야 한다.

> 공개 자료에서 확인한 범위의 기능을 이 구현 경로로 실제 만들었고, 준비된
> 입력을 넣었을 때 이 산출물이 나왔다.

이는 원제품의 비공개 모델, 코드, 데이터, 품질, 규모 또는 운영 환경과의 동등성을
뜻하지 않는다. 투자판단을 위한 대규모 사용자 조사나 시장 검증도 필수 조건이
아니다.

## 2차 조사와 실제 복제의 차이

2차 조사는 실제 복제품이 아니라 복제를 시작할 수 있는 동결된 계약이다. 공개
근거, 입력, 출력, 구현 경로, 평가 기준과 한계를 정한다.

실행 단계는 그 계약을 바탕으로 다음을 만든다.

```text
2차 replication contract
-> 실제 입력 자산 준비
-> OSS/API/코드로 최소 구현
-> 구현과 분리된 테스트 실행
-> 실제 최종 산출물 저장
-> 공개 주장과 결과의 공통점·차이 보고
```

## 완료 조건

다음 조건을 모두 만족해야 `reproduced`로 기록한다.

### 1. 실제 구현이 존재한다

- 2차 조사에서 확인한 구현 경로 중 하나를 실제로 실행한다.
- `oss_only`, `commercial_api`, `proprietary_data` 중 사용한 의존성 수준을 정확히
  기록한다.
- 더 단순한 코드로도 전체 기능이 성립하면 사용할 수 있다.
- CLI, 스크립트, 노트북이면 충분하다. UI나 별도 API는 고객에게 전달되는 기능
  자체가 UI/API 상호작용을 요구할 때만 만든다.
- 원제품의 내부 구현을 흉내 낼 필요는 없지만, 공개 주장에 포함된 전체 입력부터
  최종 출력까지의 흐름은 실제로 수행해야 한다.

### 2. 실제 입력을 처리한다

- 텍스트 기능은 실제 문서나 실행 가능한 합성 문서를 읽어야 한다.
- 문서·이미지 기능은 실제 파일을 파싱하거나 OCR해야 한다.
- 음성·영상 기능은 실제 미디어 파일을 모델이나 API에 전달해야 한다.
- 외부 작업 기능은 실제 작업 객체나 안전한 로컬 sink에 결과를 전달해야 한다.
- 입력 설명만 문자열로 전달하고 파일·모델·API를 사용한 것처럼 출력하면 안 된다.

### 3. 고객이 받는 최종 산출물이 나온다

테스트 로그나 중간 상태만으로는 완료하지 않는다. claim의 `workflow.output`과
replication contract의 `output`에 해당하는 실제 파일 또는 결과를 남긴다.

| 기능 | 최소 최종 산출물 |
|---|---|
| 생성·분석 | 완성된 텍스트, JSON, 보고서 또는 구조화 결과 |
| 검색 기반 대화 | 실제 자료를 검색해 만든 답변과 근거 인용 |
| 인터뷰 | 답변에 따라 달라진 질문, 저장된 요약과 인사이트 |
| 업무 자동화 | 조건 판정, 발생 기록과 실제 후속 작업 payload |
| 음성 | 참조 음성을 사용해 생성한 재생 가능한 음성 파일 |
| 영상·아바타 | 실제 입력에서 생성한 재생 가능한 영상 파일 |

### 4. 테스트 예시 밖에서도 동작한다

- 구현 전에 `normal`, `boundary`, `insufficient-information`의 기대 동작을 고정한다.
- 구현은 테스트 ID, 테스트 문구 또는 정답 문자열을 기준으로 분기하면 안 된다.
- 공개 개발 예시 외에 같은 계약을 따르는 새 입력을 최소 한 세트 준비한다.
- 새 입력의 기대 동작은 후보 실행 전에 고정한다.
- 새 입력에서도 같은 전체 workflow가 수행돼야 한다.
- 후보 생성과 판정은 별도 실행 단계로 둔다. 완전히 독립된 Judge가 아니면 그
  사실을 보고서에 기록한다.

### 5. 결과와 한계를 함께 남긴다

보고서는 최소한 다음을 기록한다.

- 어떤 공개 기능을 복제했는지
- 어떤 OSS, API, 데이터와 코드를 실제 사용했는지
- 실제 입력과 생성된 최종 산출물
- 정상·경계·정보 부족·새 입력의 결과
- 원 기능과 비슷하게 재현된 범위
- 확인하지 못했거나 제외한 범위
- 어느 scenario에서 처음 재현됐는지

## 테스트 전용 구현으로 보는 경우

다음 중 하나라도 해당하면 테스트가 통과해도 실제 복제로 인정하지 않는다.

- 테스트 문구, case ID, 고유 숫자나 정답 문자열을 코드에 넣고 분기한다.
- 기대 결과를 그대로 반환하거나, 테스트 fixture별 응답을 미리 저장한다.
- 문서 검색을 주장하면서 실제 문서를 읽지 않는다.
- OCR을 주장하면서 입력 이미지의 알려진 문장을 코드에서 반환한다.
- 적응형 인터뷰를 주장하면서 모든 입력에 같은 질문이나 고정 인사이트를 반환한다.
- 자연어 조건 판별을 주장하면서 하나의 테스트 예시만 인식하는 정규식을 쓴다.
- 음성 복제를 주장하면서 참조 음성을 사용하지 않고 일반 TTS 음성을 만든다.
- 상용 API scenario를 실행했다고 기록하면서 실제 API를 호출하지 않는다.
- 출력 파일은 만들었지만 해당 입력이 결과 생성에 사용되지 않는다.
- 구현과 Judge가 같은 테스트 전용 규칙을 공유해 서로 통과시킨다.

결정론적 규칙이나 단순한 코드를 쓰는 것 자체는 문제가 아니다. 공개 claim이
결정론적인 작업이고 새 입력에서도 전체 workflow를 수행한다면 가장 작은 구현이
맞다. 문제는 claim을 구현한 것이 아니라 알려진 테스트 답만 구현한 경우다.

## 최소 실행 산출물

각 scenario 실행은 최소한 다음을 남긴다.

```text
work/<company>/runs/<claim>/<scenario>/
├── evidence.json
├── spec.json
├── tests.json
├── implementation/
├── replica_outputs.jsonl
├── results.jsonl
├── artifacts/              # 생성된 문서·음성·영상 등이 있을 때만
└── report.md
```

`implementation/`에는 같은 형식의 새 입력을 다시 처리할 수 있는 실행 코드와 실행
명령이 있어야 한다. `artifacts/`는 실제 최종 산출물이 파일일 때만 만든다.

## 판정 용어

| 판정 | 의미 |
|---|---|
| `reproduced` | 실제 구현이 전체 workflow를 수행하고 모든 고정 평가를 통과함 |
| `partially_reproduced` | 실제 구현과 산출물은 있으나 계약의 일부를 충족하지 못함 |
| `not_reproduced_on_this_path` | 선택한 구현 경로와 입력으로는 재현하지 못함 |
| `execution_blocked` | 필요한 입력, 권한, 자격 증명 또는 실행 환경을 준비하지 못함 |

모든 경로가 실패해도 기능 자체가 복제 불가능하다고 확대하지 않는다. 성공해도
원제품 전체 또는 비공개 구현과 동등하다고 표현하지 않는다.

## Delphi 예시에 적용

현재 Delphi 실행은 다음 기준으로 다시 확인해야 한다.

- Digital Mind: 실제 corpus를 수집·검색하고 새 질문에 근거 있는 답변을 생성해야
  한다. 테스트 문장과 가장 많이 겹치는 원문을 그대로 반환하는 것만으로는 부족하다.
- Guided Interviewer: 사전에 알려지지 않은 답변의 세부 내용을 사용해 후속 질문과
  인사이트를 만들어야 한다. 고정 인사이트는 인정하지 않는다.
- Creator-grounded Conversation: 실제 문서와 이미지를 읽고 검색·OCR 결과로 답해야
  한다. 질문 키워드별 고정 답변은 인정하지 않는다.
- Triggered Actions: 임의의 계약 범위 내 조건과 이벤트를 처리하고 Action payload를
  실제 로컬 sink에 기록해야 한다. 고정된 fintech 예시 전용 파서는 인정하지 않는다.
- Voice: 동의받은 실제 참조 음성을 복제 경로에 넣어 생성 음성과 적용 후 음성을
  남겨야 한다. 일반 시스템 TTS는 음성 복제가 아니다.

세부 실행 순서와 디렉터리 운영은
[`replica-execution-after-pass2.md`](./replica-execution-after-pass2.md)를 따른다.
