기업명에서 회사 결과까지

회사 평가 요청 하나가 두 번의 공개 조사, 계약 동결, Operator/Builder 구현, 봉인 평가를 거쳐 claim별 결과와 회사 단위 결과로 끝나는 기본 경로입니다.

03 · Freeze gate

구현 전에 거절되는 조건

  • 1차 확정·pass_2_complete 전이거나, 요약 집계가 claim readiness와 다를 때
  • 여섯 findings 미종결, 출처 인용 누락, 경계가 unchecked일 때
  • 확정 워크플로의 단계가 step_coverage에 빠졌거나 unconfirmed일 때
  • 2차 원본 fragment가 없거나 판정이 기록 없이 바뀌었을 때
  • 평가 데이터 gap → RESEARCH_INCOMPLETE, Agent 쌍 시작 불가

04–05 · Isolation

누가 무엇을 보지 못하는가

  • Operator의 claim.json과 Builder context에는 봉인 테스트·기대값이 없음
  • Operator·Builder는 claim mailbox로 직접 주고받고, Replica Agent는 내용을 중계하지 않음
  • 최종 판정은 Builder의 주장이 아니라 봉인 case·반복·변형 관계 결과로 결정
  • 단계를 제외한 계약은 모두 통과해도 최대 partially_reproduced

06 · Outputs

남는 것

  • claim별 공개 run: 코드, 예시, replica-result.json
  • company-claims.json: 실행하지 않은 claim과 사유까지 전체 분모
  • run-replica·experience로 새 입력 직접 실행
