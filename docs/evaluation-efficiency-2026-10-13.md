# Delphi 1번 기능: 최종 평가 비용 최적화 결과

같은 앱·입력·평가 범위를 유지한 비교에서 **$4.99 → $3.31, 33.7% 절감**을 확인했다. 코드 검사에서 이전 실행의 앱 코드 캐시를 재사용한 이점은 별도 측정으로 보정했다.

금액은 **CLI 정가 환산액**이다. 개선 후 총액은 실제 실행 영수증에 공통 입력 생성비를 더하고, 코드 검사 비용을 캐시를 분리해 다시 측정한 값으로 바꾼 **항목별 보정 비교**다. 하나의 실행에서 그대로 청구된 금액이라는 뜻은 아니다.

## 범위와 결과

| 항목 | 개선 전 | 개선 후 |
|---|---:|---:|
| 비교 비용 | $4.986270 | $3.306536 |
| 브라우저 판단 모델 호출 | 148 | 126 |
| 실제 브라우저 행동 기록 | 148 | 145 |
| 사례 / 기대조건 | 10 / 35 | 10 / 35 |
| 충족 / 불충족 / 미평가 | 35 / 0 / 0 | 35 / 0 / 0 |
| 독립 코드 검사 | 통과 | 통과 |

행동 기록 3개 차이는 테스터가 선택한 조작·대기 경로의 차이다. 사례·단계·기대조건을 삭제하거나 행동 수 예산을 줄이지 않았다. 원자 행동마다 화면을 저장했고, 모든 충족 판정의 근거 이벤트·화면 파일이 존재한다. 입력 생성 결과, 앱 해시, 계획 해시, 역할별 모델도 일치한다.

## 비용 구성

| 역할 | 개선 전 | 개선 후 비교값 |
|---|---:|---:|
| 브라우저 판단 | $2.646883 | $1.599641 |
| 사례별 의미 판정 | $1.343962 | $0.922162 |
| 코드 검사 | $0.534028 | $0.331456 |
| 앱 내부 모델 | $0.219863 | $0.211743 |
| 입력 생성 | $0.241534 | $0.241534 |

개선 후 원 실행 자체는 $2.779540였다. 공통 입력 생성비 $0.241534만 더하면 $3.021074(39.4% 절감)이지만, 코드 검사에서 61,379토큰을 캐시로 읽었다. 개선 전 코드는 대량 신규 쓰기였으므로 이를 그대로 첫 평가 절감으로 해석하지 않았다.

동일한 코드 검사 JSON 앞에 의미 없는 고유 표식을 추가해 앱 코드 접두부의 캐시를 분리했다. 모델·스키마·지시문·파일·평가 범위는 동일하다. 추가 검사는 통과했고, 앱 검사 입력 59,711토큰을 5분 캐시에 새로 썼다. 측정액 **$0.331456**를 원 검사의 **$0.045994** 대신 사용했다. 공통 CLI 접두부 2,065토큰은 여전히 캐시 읽기이므로 모든 캐시 공유를 완전히 제거한 실험은 아니다.

중단 전후 기준선 지출은 $5.156510이며, 중단으로 버린 $0.170240는 절감률 기준에서 뺐다. 개선 후 평가와 추가 코드 검사까지 이번 평가 비교에 쓴 총액은 **$8.267506**다. 구현·조사·토론 세션 사용량과 브라우저/CPU/저장 비용은 이 표의 범위가 아니다.

## 적용한 변경

1. 현재 화면에서 확인한 입력·선택·제출을 한 번에 계획한다. 코드는 각 행동을 실제로 수행하고 DOM 대상, 필드 전체 값, 화면 변화와 오류를 검사한다. 제출은 한 계획에 한 번이며 결과를 해석할 때 다시 모델을 호출한다.
2. 모델 응답을 기다리는 동안 화면이 바뀌었으면 첫 행동 전에도 멈춘다. 다른 필드·옵션·ARIA 변화, 노드 교체, 팝업·일시적 오류와 증거 저장 실패를 보존한다. `effect=ok`를 업무 성공 판정으로 쓰지 않는다.
3. 평가용 Claude 호출에만 5분 캐시를 적용했다. 실제 영수증에서 tester·Judge·코드 검사의 5분 쓰기를 확인했다. 앱 내부 호출과 전역 설정은 바꾸지 않았고, 모델·호출별 격리도 유지했다.
4. 비교에서는 입력만 재사용하고 브라우저 실행·판정·코드 검사는 새로 수행한다. 중단 재개와 비교 입력 재사용은 분리하고 해시·설정을 확인한다.

판단 호출은 148→126회로 14.9% 줄었다. 비용 33.7% 절감은 호출 감소와 캐시 설정 등을 합친 관측 결과이며, 각 변경의 독립적인 인과 효과를 분리한 실험은 아니다.

## 검증과 한계

- 전체 저장소 시험 **394개 통과**. 이 가운데 행동 계획 관련 정상·오류 주입 시험 20개가 통과했다. 잘못된 입력 수락, 노드 교체·모호성, 화면 변경, 관측 실패, 오류·팝업, 저장 실패, 호출/행동 예산을 검사했다.
- 35개 조건의 전후 판정 변화 0개. 두 본 평가와 추가 코드 검사의 독립 모델 판정이 통과했다. 같은 scope와 후보를 검증했으며 별도 구현 수정은 없었다.
- 묶음 계획 126개 중 복수 행동 계획 40개, 거부된 계획 2개. 37개 계획에서 나머지 행동을 취소했다(이동 27, 필드 변화 4, 새 필드 4, 텍스트 변화 2). 취소된 행동 48개를 성공으로 세지 않았다.
- 한 기업의 한 기능으로 한 쌍을 비교했다. 모든 제품·입력에서 같은 절감률이나 판정 정확도를 보장하지 않는다.
- 기존 조사에서 제외한 자동 동기화, YouTube·팟캐스트 검색 수집, 다중 화자 분리, 실시간 영상 아바타, 전이중 실시간 통화, Pro Voice는 그대로다. **전체 기능 판정은 부분 재현**이며, 구현한 범위의 35개 조건 충족과 구별한다.
- 사례 간 조작 절차 재사용(B2), 추가 증거 압축, 동적 시스템 프롬프트 변경은 이번 적용에서 제외했다.
