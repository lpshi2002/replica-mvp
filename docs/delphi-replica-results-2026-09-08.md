# Delphi AI 복제 결과 — 어떤 기능을 만들었고, 어디까지 작동했나

실행일: 2026-09-08 · 브랜치: `codex/replica-completion-test`

이번에 복제하려 한 것은 **한 사람의 지식을 모으고, 그 지식으로 대신 대화하고, 대화 상황에 따라 후속 업무를 처리하는 세 기능**이다. Delphi에서는 창작자·전문가·코치 등이 자신의 지식과 관점을 담은 AI 분신인 **Digital Mind**를 만드는 데 쓰이는 기능들이다. 아래 원기능 설명은 이번 실행의 2차 조사에 보존된 공개 제품 설명을 기준으로 한다.

세 기능 모두 실행 코드와 일부 결과물을 만들었지만, **전체 요구사항을 만족한 기능은 없다.** 최종 판정은 모두 부분 재현(`partially_reproduced`)이다. 새 자료로 대화하고 인터뷰 답변을 저장하는 동작은 확인했고, 자동 작업은 새 입력에서 출력 파일 오류가 났다.

## 정확히 어떤 기능을 복제했나

| 기능 | 누구에게 어떤 도움이 되는가 | 이번 복제품에 넣는 것 | 이번 복제품이 내놓는 것 |
|---|---|---|---|
| **① 내 지식·말투로 대신 답하는 AI 분신** — 자료 기반 대화 | 전문가나 창작자가 같은 질문에 반복해서 답하는 일을 줄임 | 그 사람의 자료를 담은 텍스트, 말투·안전 규칙, 이전 대화, 새 질문 | 자료에 근거한 답변과 출처. 답할 근거가 없거나 안전 규칙에 해당하면 별도 상태 반환 |
| **② 대화 상황에 맞춰 후속 업무를 하는 기능** — Delphi Actions | 대화를 읽고 답장하거나 고객을 분류하는 일을 자동화 | “이런 상황이면 이렇게 해라”라는 지시, 새 메시지·사용자 정보, 승인 여부 | 조건 판단, 실행할 작업, 실행 기록과 로컬에 저장한 답장·태그·속성 변경 결과 |
| **③ 인터뷰로 내 노하우를 지식 자료로 만드는 기능** — Delphi Interview | 글을 따로 쓰지 않고 질문에 답하면서 자신의 관점과 노하우를 정리 | 현재 주제와 질문, 사용자가 작성한 답변 | 이어서 물어볼 주제, 답변의 핵심 요약, 원문과 함께 저장한 기록 |

세 기능은 각각 **질문에 답하기 / 대화 뒤에 행동하기 / 대화에 쓸 지식을 모으기**에 해당한다. 이번 결과물은 기능별로 따로 실행하는 세 묶음이다. 인터뷰에서 저장한 지식이 자동으로 AI 분신에 들어가고, 그 분신의 대화가 자동 작업으로 이어지는 통합 흐름까지 구현·검증한 것은 아니다.

현재 사용 형태는 **터미널에서 정해진 형식의 JSON 입력을 넣고 결과를 받는 방식**이다. JSON은 자료·질문·답변 같은 항목에 이름을 붙여 저장하는 텍스트 형식이다. 사람이 클릭해서 사용하는 Delphi의 화면, 음성·영상 통화, 회원가입·결제까지 만든 결과는 아니다.

## 최종 평가 결과

| 기능 | 선택한 구현 경로 | 통과 | 판정 |
|---|---|---:|---|
| 자료 기반 대화 | Haystack 검색 + Codex 모델 생성 | 4/6 | 부분 재현 |
| 상황별 자동 작업 | Codex 모델 판단 + Dagu 실행 + 로컬 작업 기록 | 5/7 | 부분 재현 |
| 인터뷰·인사이트 저장 | Codex 모델 생성 + Python sqlite3 저장 | 5/6 | 부분 재현 |

결과는 각 기능의 **두 번째 최종 평가로 보존된 구현**을 기준으로 한다. 이후 보완 중이던 코드는 이 결과에 포함하지 않는다. 숫자는 **통과한 평가 사례 수 / 전체 사례 수**이며, 4/6을 “제품의 67%를 복제했다”는 뜻으로 읽으면 안 된다. 표본이 작고 기능별 기준도 다르다.

| 평가 유형 | 자료 기반 대화 | 상황별 자동 작업 | 인터뷰·인사이트 저장 |
|---|---:|---:|---:|
| 정상 입력 | 0/1 | 0/1 | 1/1 |
| 경계 입력 | 1/1 | 2/2 | 1/1 |
| 정보 부족 | 1/1 | 0/1 | 0/1 |
| 새로운 입력 | 1/1 | 1/1 | 1/1 |
| 입력 변형에 따른 관계 검사 | 1/2 | 2/2 | 2/2 |

‘정보 부족’은 답할 근거가 없거나 답변 내용이 충분하지 않을 때의 처리다. ‘입력 변형’은 표현을 바꿔도 같은 의미로 처리하는지, 중요한 사실을 바꾸면 결과도 맞게 바뀌는지를 검사한다. 정상 입력에서도 실패가 있다는 점 때문에 현재 결과를 안정적으로 사용할 수 있는 완성품으로 보지 않는다.

세 후보 모두 최종 평가 상태는 `FAILED`, 재현 판정은 `partially_reproduced`다. 요구한 처리 과정을 실제로 수행하는지, 특정 예제에만 맞춰 만든 것은 아닌지를 보는 구현 검토도 미통과로 기록돼 있다. 실행 중 평가기에 전달하는 근거를 보완했지만, 기존 결과를 소급해 통과로 바꾸지는 않았다.

## 기능별 실제 산출물과 새 입력 실행

새 입력 실행은 평가된 두 번째 구현의 코드를 수정하지 않고 수행했다. 아래 관찰은 구현 이후 추가로 확인한 결과이며, 앞의 동결된 평가 통과 수에 합산하지 않는다.

### ① 내 지식·말투로 대신 답하는 AI 분신

**원래 어떤 기능인가.** 창작자나 전문가가 제공한 글·지식·관점을 바탕으로 AI가 다른 사람의 질문에 대신 답하는 기능이다. 예를 들어 강사의 자료를 읽은 AI에게 수강생이 질문하면, 강사의 자료와 설정한 말투를 따라 답한다. 근거가 없으면 모른다고 하고, 민감한 질문에는 정해진 안내를 해야 한다.

**이번에 복제한 범위.** 텍스트로 제공한 자료에서 질문과 관련된 내용을 검색하고, 그 내용을 근거로 답변을 생성하는 흐름이다. 말투·안전 규칙도 입력으로 받는다.

```text
자료 + 말투·안전 규칙 + 이전 대화 + 새 질문
→ 관련 자료 검색 → 근거와 규칙에 맞춰 답변 생성
→ 답변·출처 반환, 또는 정보 부족·전문가 안내 상태 반환
```

자료와 말투 규칙은 사용자가 직접 넣는다. 파일 업로드·웹사이트 자동 수집, 말투의 자동 학습, 목소리 복제·영상 아바타는 이번에 검증한 기능에 포함되지 않는다. “실제 그 사람과 구별할 수 없는 답변”을 재현했다고 판단하지도 않는다.

검색에는 Haystack, 문장 생성에는 Codex 모델 런타임을 사용했다. 확인한 의존성 버전은 `haystack-ai 2.26.1`, `codex-cli 0.153.4`다.

**실제로 나온 결과.** 처음 구현할 때 쓰지 않은 수리 도서관 안내 자료를 넣고 “언제 전등을 가져갈 수 있고, 무엇을 준비해야 하며, 진단비는 얼마인가?”라고 질문했다. 다음 정보를 포함한 답변을 생성했다.

- 목요일 오후 2~5시 방문, 작업대 사전 예약, 전원을 분리한 상태로 물건 지참.
- 전선 절연이 손상됐으면 수리 연기, 진단비 7크레딧, 부품비 별도.
- 제공한 두 자료를 모두 인용하고, 제목 없이 한 문단·세 문장 이하로 답하라는 문체 조건 준수.

해당 실행은 약 **8.8초**에 완료됐다. 이 입력에서 자료 검색부터 답변까지 동작한 것은 확인했지만, 동결 평가의 정상 입력 1건과 변형 검사 1건이 미통과이므로 계약 전체의 안정적인 충족은 확인되지 않았다.

### ② 대화 상황에 맞춰 후속 업무를 하는 기능

**원래 어떤 기능인가.** Delphi Actions는 사용자가 정한 조건과 대화 맥락에 따라 답장·알림·고객 분류 같은 후속 업무를 수행하는 기능이다. “강의 영상을 못 본다는 문의가 오면 어떤 강의인지 물어보고, 해당 고객을 영상 지원 대상으로 분류해 줘”처럼 업무를 말로 설정하는 것이 대표적인 사용 장면이다.

**이번에 복제한 범위.** 지시를 실행 계획으로 바꾸고, 실제 메시지 내용이 조건에 해당하는지 판단한 뒤, 승인 조건을 확인하고 로컬에 후속 작업을 기록하는 흐름이다. 잘못된 조건에서 실행하지 않기, 승인을 기다리기, 같은 이벤트를 중복 처리하지 않기, 필수 정보가 없으면 다시 묻기도 평가 대상에 포함했다. 이 조건들이 모두 통과했다는 뜻은 아니다.

```text
업무 지시 + 새 메시지·사용자 정보 + 이전 대화 + 승인 여부
→ 지시 해석 → 조건 일치 여부 판단 → 승인 확인
→ 작업 실행 → 답장·태그·속성 변경과 실행 기록을 로컬 파일에 저장
```

여기서 ‘로컬’은 이 컴퓨터 안에 결과를 저장한다는 뜻이다. 답장을 실제 이메일이나 Slack으로 보내지는 않는다. 따라서 메시지 내용과 실행 기록을 만드는 단계까지 시험했으며, 고객 시스템에 전달되는 전체 연동을 재현한 것은 아니다.

모델 판단에는 Codex, 작업 실행에는 Dagu를 사용했다. 확인한 의존성 버전은 `dagu 2.16.2`, `codex-cli 0.153.4`다. 평가된 구현 묶음에는 로컬 작업 기록인 `sink.json`이 보존돼 있다.

**실제로 나온 결과.** 새 입력에서 교육 영상에 접근하지 못하는 상황을 주고, 문제가 생긴 강의를 묻는 답변과 `playback-help` 태그 추가를 함께 요청했다. 실행 약 **9.3초** 후 CLI가 다음 오류로 종료됐다.

```text
error: output artifact must be an actual file inside the runtime directory
```

이 오류는 결과로 제시한 파일이 실제 실행 폴더 안의 파일인지 확인하는 단계에서 실패했다는 뜻이다. 검증된 최종 출력이 반환되지 않아 이 새 입력의 작업 완료는 확인할 수 없다. 기존 동결 평가에서도 정상 입력과 정보 부족 입력이 각각 1건씩 미통과였다. 이번 증거만으로 임의의 새 조건에 안정적으로 자동 작업을 수행한다고 판정할 수 없다.

### ③ 인터뷰로 내 노하우를 지식 자료로 만드는 기능

**원래 어떤 기능인가.** Delphi Interview는 AI가 창작자에게 질문하면서 그 사람의 생각과 노하우를 모으는 기능이다. 답변에서 더 물어볼 주제를 찾고, 관점이나 일하는 방식을 짧게 정리해 Digital Mind에 넣을 지식 조각으로 저장한다. 글을 처음부터 따로 작성하는 대신 인터뷰에 답하면서 자신의 지식을 쌓는 용도다.

**이번에 복제한 범위.** 현재 주제·질문·텍스트 답변을 받아 다음에 더 물어볼 주제와 짧은 요약을 만들고, 원문과 함께 저장하는 흐름이다. 답변이 부족하면 완성된 지식으로 저장하지 않고 추가 정보를 요구하는 것도 평가 대상이다.

```text
현재 인터뷰 주제 + 현재 질문 + 사용자의 텍스트 답변
→ 답변이 충분한지 판단 → 후속 주제와 핵심 요약 생성
→ 원문·후속 주제·요약을 데이터베이스에 저장 → 저장 ID로 다시 읽어 확인
```

현재 질문은 입력으로 받으며, 출력은 다음에 다룰 **주제**다. 화면에서 AI가 인터뷰를 처음부터 진행하는 전체 경험, 음성 인식, 원제품의 주제 진행률 계산, 실제 Delphi Digital Mind에 학습 자료를 넣는 연결은 이번 구현 범위에 포함되지 않는다.

생성에는 Codex, 저장에는 이 컴퓨터에 파일로 남는 SQLite 데이터베이스를 사용했다. 2차에서 선택한 경로는 `s-native-sqlite`이며, 확인한 의존성은 Python `3.12.12`의 sqlite3 모듈과 `codex-cli 0.153.4`다. 다른 조사 대안인 Aural·Supabase를 실행한 결과는 아니다.

**실제로 나온 결과.** 새 입력으로 “초보자에게 수리를 가르칠 때 무엇을 기준으로 하는가?”에 대한 답변을 넣었다. 답변에는 저전압의 되돌릴 수 있는 작업부터 시작하고, 안전 절차를 설명하게 하며, 멈추고 전문가에게 물어볼 시점을 가르친다는 내용이 들어 있었다.

- 답변에 맞춰 “언제 멈추고 전문가에게 도움을 요청해야 하는지 가르치는 방법”이라는 후속 주제 생성.
- 원문에 근거한 요약과 저장 ID 반환.
- 실제 SQLite 파일에서 같은 저장 ID의 행 재조회.
- 저장된 원문이 입력과 같고, 저장된 요약이 응답과 같은지 확인.

해당 실행은 약 **19.0초**에 완료됐다. 반환된 저장 ID는 `5832cc7c-96a6-4872-9b7f-456a064279e9`다. 생성부터 물리적 저장·재조회까지 확인했지만, 동결 평가의 정보 부족 입력 1건과 구현 검토 미통과가 남아 있다.

## 구현은 어디에서 멈췄나

두 번째 평가 이후 세 번째 제출을 준비했지만, 세 쌍 모두 검증된 직접 피드백과 종료 절차를 완성하지 못해 `EXECUTION_ABORTED`로 종료됐다. 같은 Agent ID로 제한된 복구를 시도했으며, 자동 작업은 원래 개발 예산도 소진했다. 세 번째 후보의 최종 평가 결과는 없다.

전체 하네스는 `EXECUTION_COMPLETED_WITH_FAILURES`로 종료됐다. 이는 실패를 포함해 실행이 끝났다는 의미이며, 세 복제품이 모두 완성됐다는 의미가 아니다. 두 번째 평가의 부분 결과와 이전 시도 기록은 보존돼 있다. [하네스 종료 기록](evidence/delphi-ai-2026-09-08/agent-harness.json)

## 이번 결과로 확인한 범위

공개 기술과 모델 런타임을 조합해 자료 검색·답변, 인터뷰 요약·저장이라는 고객 작업의 일부를 실제로 수행할 수 있었다. 자동 작업도 실행 코드와 일부 산출물은 확보했지만 새 입력에서 완료를 확인하지 못했다. 세 기능 모두 아직 전체 계약을 만족한 복제품으로 볼 수 없다.

원제품을 동일 입력으로 실행한 비교 결과는 이번 실험에 없다. 따라서 Delphi와의 품질 동등성, 비공개 기술 재현, 운영 규모에서의 안정성이나 기업 전체의 해자 수준은 판단하지 않는다. 특히 Agent 피드백·종료 절차의 실패를 Delphi 기술 자체의 복제 장벽으로 해석하지 않는다.

세 경로 모두 생성 단계에 Codex 모델 런타임을 사용했으므로 오픈소스 소프트웨어만으로 재현한 결과가 아니다. 전체 개발 시간·사람 개입·경제적 비용에는 미측정 항목이 남아 있다. 위 처리 시간은 새 입력 한 번의 관측값이며 평균 성능이나 운영 비용을 의미하지 않는다.

## 실행 조건과 원본 기록

- 조사 입력: 기존 조사에서 부족한 부분만 구현 전에 보완한 [이번 실행의 2차 조사 JSON](evidence/delphi-ai-2026-09-08/research.json). 원본 조사와 구현 전에 정한 평가 기준은 보존했다. 선택한 세 기능 모두 구현·평가했다.
- 구현 Agent: 기능마다 **Astra medium Operator + Terra high Builder** 한 쌍, 총 세 쌍.
- 병렬 실행: 초기 시작 오류를 복구한 뒤 세 쌍의 실행 세션이 겹쳤다(`peak_active_pairs: 3`). 환경의 활성 Agent 한도가 조율자를 포함해 7개여서 대기 턴을 반환하고 같은 ID로 재개했다. 모든 Agent가 계속 동시에 추론한 것은 아니다.
- 평가: 기능당 두 번, 총 여섯 번 최종 평가했다. 개발과 별도 실행 단계에서 평가했지만 Judge는 `same_session`으로 기록돼 있어 완전히 독립된 평가로 보지 않는다.
- 근거 수준: 공개 제품 설명을 바탕으로 정한 업무 기준(`public`)을 검사했다. 실제 Delphi 고객 데이터나 같은 입력에 대한 원제품 출력과 직접 비교한 평가가 아니다.
- 보존한 결과물: 실행 코드, 실행 방법·의존성을 적은 manifest, JSON 입출력, 평가 결과, 생성한 파일.

전체 새 입력의 명령·입출력·처리 시간은 [실행 기록](evidence/delphi-ai-2026-09-08/fresh-input-execution-check.json), 실행 브랜치·소스와 조사 해시는 [실행 환경 기록](evidence/delphi-ai-2026-09-08/run-context.json)에 있다.
