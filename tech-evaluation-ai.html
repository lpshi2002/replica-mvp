2. 기술성 9개를 조사·검증 업무로 바꾸기

“평가항목을 이해했다”와 “그 항목을 검증했다”는 다릅니다. 예를 들어 논문에 성능 수치가 있다는 것은 논문상 주장을 확인한 것이지 현재 판매 제품의 동일 성능을 검증한 것은 아닙니다.

공식 기술성 항목 실제로 확인할 질문 조사·검증 작업으로 구체화한 예시 외부에서 확인하기 어려운 부분
① 기술의 진행 정도 아이디어, 시제품, 실증, 실제 운영 중 어디까지 왔는가? 개발 연혁과 제품 버전을 정리하고, 발표한 완료 시점과 실제 시험·출시·납품 근거를 대조합니다. 계획과 완료를 분리합니다. 내부 개발 진척도, 미해결 결함, 고객 검수 결과
② 기술의 신뢰성 주장하는 성능이 어떤 조건에서 입증됐는가? 성능 수치마다 시험기관·데이터·표본·시험조건·실시일·제품 버전을 붙입니다. 회사 자체 시험과 독립 시험을 구분합니다. 원시 시험데이터, 실패 사례, 재현 시험
③ 기술의 자립도 핵심 부분을 자체 개발·보유하는가? 외부 기술에 얼마나 의존하는가? 핵심 기능을 구성요소로 나누고 자체 개발, 외주, 라이선스, 외부 API 등의 근거를 연결합니다. 특허 소유자와 실제 사업 주체도 대조합니다. 라이선스 계약, 외주 결과물의 권리 귀속, 공급 중단 시 영향
④ 기술의 차별성 기존 기술보다 정확히 무엇이 다른가? 비교할 경쟁 기술을 선정하고 동일 조건의 성능·비용·속도·제약을 비교합니다. 서로 다른 시험조건의 수치를 한 표에서 우열로 해석하지 않습니다. 동일 조건의 직접 비교시험, 실제 고객 환경 성능
⑤ 기술의 모방난이도 경쟁사가 같은 결과를 구현하기 어려운 이유는 무엇인가? 특허의 보호 대상, 데이터 확보 경로, 노하우, 시스템 통합 난이도를 분해합니다. 특허 수나 개발기간만으로 방어력을 판단하지 않습니다. 영업비밀, 데이터의 배타적 권리, 실제 우회 구현 가능성
⑥ 기술의 확장성 같은 핵심기술을 다른 제품·고객·산업에 적용할 수 있는가? 기존 적용 사례와 신규 적용 계획을 구분하고, 재사용 가능한 부분과 추가 개발·검증이 필요한 부분을 표시합니다. 신규 적용의 실제 개발비, 고객별 커스터마이징 부담
⑦ 연구개발 활성화 수준 연구개발 활동이 지속되고 성과로 연결되는가? 연구개발 투자, 인력, 프로젝트, 특허·논문·제품 개선의 시계열을 정리합니다. 투입과 산출을 구분합니다. 프로젝트별 예산·실적, 연구개발비 세부 내역
⑧ 경영진의 전문성 이 기술과 사업을 수행한 경험이 있는가? 공개 경력과 과거 프로젝트에서의 실제 역할·성과를 연결합니다. 소속 기업의 성과를 개인 성과로 그대로 옮기지 않습니다. 실제 의사결정 역량, 역할 기여도, 평판 조회
⑨ 기술인력 등 관리체계 핵심 인력이 빠져도 기술 개발과 운영을 지속할 수 있는가? 조직 구성, 핵심 인력 의존도, 개발·품질·보안 절차, 문서화 및 인수인계 체계의 증거를 확인합니다. 인력 이탈 현황, 내부 운영 절차의 실효성, 보상·유지 정책

4. 공개자료로 아직 재현할 수 없는 것

LIMIT 01 세부 증거 → 점수 규칙

어떤 증거에 몇 점을 주는지에 관한 세부항목별 채점 기준은 공개자료만으로 완결되지 않습니다.

LIMIT 02 최신 배점·등급 변환

적용 산업·기관별 최신 배점과 등급 변환 규칙을 공식적으로 전부 재현할 수 없습니다.

LIMIT 03 전체 내부 심의 기록

기업별 전체 평가보고서, 내부 심의 기록, 모든 추가 질의와 답변은 공개 데이터셋으로 확보되지 않습니다.

5. 외부 팀이 실행할 수 있는 공개자료 7단계 파이프라인

공식 평가기관의 업무 흐름을 참고하되, 회사명 또는 URL과 공개자료만으로 실행 가능하도록 다시 자른 MVP용 파이프라인입니다. 기술사업계획서, 기업 내부문서, 비공개 답변을 전제로 하지 않습니다.

단계 해야 할 작업 산출물 AI와 사람의 역할
1. 대상 식별 회사명·URL에서 법인, 핵심 제품·기술, 분석 기준일을 식별 대상 회사·기술 범위표 AI가 후보를 정리하고 사용자가 대상만 확인
2. 공개자료 탐색·수집 회사 홈페이지, DART 등 공시, 특허, 논문, 인증·시험기관, 정부·경쟁사 공개자료를 검색하고 출처·날짜를 저장 출처목록, 원문 링크, 수집 로그 검색·중복 제거·출처 메타데이터 정리를 자동화
3. 주장 분해·항목 연결 공개자료의 “성능 우수”, “자체 개발”, “고객 적용 완료”를 검증 가능한 주장으로 분해하고 9개 항목에 연결 항목별 주장–증거 대응표 AI가 초안을 만들되 원문 위치를 반드시 보존
4. 외부 조사·교차검증 비교 기술, 특허, 논문, 인증·시험 결과, 제품 공개자료를 회사 공개주장과 대조 경쟁 비교표, 지지·반대 근거, 불일치 목록 검색·정리·대조 자동화, 비교 적절성은 사람 검토
5. 비교조건 검증 수치의 단위·기간·데이터셋·제품 버전·시험주체·측정방법이 실제로 같은지 확인 비교가능 / 일부 비교 / 직접 비교 불가 상태표 AI가 조건을 대조하고 애매한 비교는 판단을 보류
6. 미확인 영역 표시·질문 생성 공개자료로 확인할 수 없는 외주범위, 라이선스, 원시 시험데이터, 내부 운영정보 등을 추정하지 않고 명시 증거 공백 목록, 추가 확인 필요자료, 질문 목록 AI가 확인 불가 사유와 다음 확인 포인트를 생성
7. 근거기반 보고서 생성 확인된 사실, 상충 근거, 미확인 영역, 전문가 확인사항을 원문 링크와 함께 정리 근거가 연결된 기술성 조사 보고서 AI는 조사 결과를 구조화하고 사람은 출처·과잉판단을 검토

3. 제품의 중심은 4개 작업 모듈

공개자료 검색 자체가 제품의 끝이 아닙니다. 사람이 평가 준비 과정에서 반복하는 분해·정리·검토·질의 준비를 하나의 작업공간으로 묶어야 리서치 프로젝트를 넘어섭니다.

MODULE 01

Claim Workspace

문서나 웹페이지를 작은 검증 주장으로 나누고 평가항목, 원문, 지지·반대 근거, 비교조건과 함께 확인 수준·자료 수집 상태·다음 행동을 관리합니다.

6. MVP가 실제로 접근하는 데이터

자료 종류 MVP에서 하는 일 확인할 수 없는 부분
회사 공식 공개자료 제품·기술 페이지, IR, 보도자료, 공시에서 기술 주장과 개발·상용화 이력을 추출 회사 내부에서만 존재하는 시험결과·개발현황
독립 공개자료 특허·논문·인증·시험기관·정부·언론·경쟁사 자료로 회사 주장을 교차검증 동일 조건 시험이 공개되지 않으면 직접적인 성능 우열
공개자료로 확인하지 못한 영역 자료 미발견과 검색·접근 실패를 구분하고, 내부자료 확인이 필요한 이유와 다음 질문을 기록 외주계약, 라이선스 범위, 원시 시험데이터, 내부 인력관리, 영업비밀 등

기술사업계획서나 기업 제공문서를 받는 상황을 MVP 성공조건으로 두지 않습니다. 현재 제품은 처음부터 끝까지 공개자료만으로 조사 결과를 만들 수 있어야 합니다.

7. MVP 범위와 초기 사용자 가설

고객 가설

누가 먼저 쓸 수 있는가

  • 상장 준비기업의 기술·IR 담당자
  • 기술평가 자문기관
  • 특허법인
  • 주관사 실무자

NICE평가정보가 상장 컨설팅에 차이분석, 모의평가·리뷰, 기술사업계획서 완성 등의 업무를 제시한다는 점은 관련 업무가 존재한다는 근거입니다. 특정 고객이 이 제품을 실제 구매할 것이라는 증거는 아닙니다.

MVP

9개 전체 분류 + 3개 항목 우선 검토

  • 기술의 진행 정도 — 개발·실증·출시·납품 단계의 공개 근거 확인
  • 기술의 신뢰성 — 성능 근거의 조건·시험주체 확인
  • 기술의 차별성 — 동일 조건 경쟁 비교

자립도는 특허·파트너·외부 API 등 공개근거까지만 부분 확인하고, 외주·라이선스·권리귀속은 “공개자료로 확인 불가”로 표시한 뒤 추후 회사 확인이 필요한 질문으로 남깁니다.

9. 정확한 AI 워크플로우

STEP 01

회사명 또는 회사 URL 입력

사용자가 아는 최소 정보만 받습니다. 핵심 제품명이 없어도 공식 홈페이지에서 제품·기술 후보를 먼저 찾습니다.

STEP 02

공개자료 자동 수집

회사 공식 페이지, DART 등 공시, 특허, 논문, 인증·시험자료, 보도자료와 경쟁사 자료를 검색하고 URL·발행주체·날짜를 보존합니다.

STEP 03

공개된 기술 주장을 검증 단위로 분해

“정확도 98%”, “국내 최초”, “상용화 완료”, “자체 개발”처럼 외부에서 확인할 수 있는 문장과 수치를 작은 주장으로 나눕니다.

STEP 04

Evidence Schema로 정규화

각 Claim에 원문·출처·날짜·작성주체·평가항목·비교조건을 연결하고, 확인 수준·자료 수집 상태·다음 행동을 별도 필드로 기록합니다.

STEP 05

기술성 9개 항목 + Methodology 적용

Claim을 9개 항목에 연결하고, 진행 정도·신뢰성·차별성에는 MVP 체크리스트를 적용합니다. 향후 이 체크리스트를 기관 방법론으로 교체할 수 있게 분리합니다.

STEP 06

독립·상충 근거 검색과 비교조건 대조

회사 자료의 재인용을 별도 근거로 세지 않고 독립 출처를 찾으며, 수치·단위·기간·제품 버전·데이터셋·시험주체가 실제로 같은 조건인지 비교합니다.

STEP 07

확인 수준·수집 상태 + Evidence Gap 생성

주장의 확인 수준과 상충 근거를 기록하고, 자료별로 확보·미발견·검색 또는 접근 실패를 구분합니다. 내부자료 요청·전문가 검토 등 필요한 다음 행동은 별도로 남깁니다.

STEP 08

Reviewer Queue 생성

상충근거, 비교조건 불일치, 자료 부족, 전문가 판단 필요 항목을 우선순위로 묶어 사람이 어디부터 봐야 하는지 정리합니다.

STEP 09

검토·질문·보고서 확정

사람이 원문과 과잉판단을 확인하고 미해결 항목은 필요 증빙·질문으로 확정합니다. 검토 완료까지 걸린 시간도 기록해 실제 시간절약을 측정합니다.

세 정보는 함께 기록합니다.
예: 성능 주장 일부 확인 · 관련 시험보고서 접근 실패 · 접근 재시도와 전문가 검토 필요. 자료를 찾지 못했다는 사실만으로 자료가 존재하지 않거나 기술력이 부족하다고 판단하지 않습니다. 내부자료가 필요한 경우에는 공개근거만으로 해결할 수 없는 이유를 명시합니다.
같은 회사 보도자료를 여러 기사가 재인용했다고 해서 독립적인 검증 근거가 여러 개 생긴 것은 아닙니다. 출처 계보를 추적해 사실상 같은 원천인지 구분해야 합니다.

12. 실제 Claim 검토 화면 예시

example_claim.json
회사 주장
“정확도 98%로 경쟁사 92%보다 우수하다.”
확인된 내용 · 회사 공식 페이지가 정확도 98%라고 주장주장 확인

기업별 쟁점 예시 · 가상 사례
2025년 IR의 98% 수치는 데이터셋 A에서 측정됐고, 공개 인증시험은 제품 v1을 대상으로 합니다. 현재 판매 제품 v2에 같은 성능을 적용할 수 있는 근거는 확인하지 못했습니다.

구체적인 추가 질문
제품 v2를 데이터셋 A에서 시험한 결과가 있습니까? IR 수치의 측정 제품 버전과 인증시험 결과를 연결할 수 있는 자료를 요청합니다.

목표는 보고서를 자동 작성하는 데서 끝나지 않습니다. 평가자가 원문을 다시 뒤지는 시간을 줄이고, 검토가 필요한 Claim과 그 이유를 바로 보여주는 것이 제품의 핵심입니다.

13. 후속 확장: Replica는 보조 증거 모듈

기존에 구상한 Replica를 연결한다면 제한된 기능을 같은 조건에서 시험하는 보조 모듈로 사용할 수 있습니다. 다만 일부 기능 재현 성공 = 기업 전체가 쉽게 모방 가능도 아니고, 재현 실패 = 강한 기술 방어력도 아닙니다. 재현 결과는 하나의 증거로만 취급해야 합니다.
Validation

이 MVP가 제품인지 여부는 업무 품질과 사람 시간 절감으로 검증합니다.

초기 제품이 먼저 증명해야 할 것은 등급 예측력이 아니라, 사람이 하던 Claim 추출·분류·근거 대조·쟁점 탐지·질의 준비·검토를 더 정확하고 빠르게 수행하는지입니다.

첫 실험: 한 산업, 소수 기업, 특정 기술 주장
같은 산업에서 공개자료가 풍부한 기업과 부족한 기업을 함께 선정해 근거 연결부터 사람의 검토 완료까지 시험합니다. 우선 판단 기준은 중요한 쟁점의 누락, 불필요한 경고, 수정까지 포함한 총 검토 시간입니다. 기업·기술·문서·버전에 연결된 구체적 질문을 만드는지도 확인합니다. 정확도·시간절약률은 실험 후 보고하고, 개발기간은 구현 범위에 따른 추정치로 표시합니다.
검증 대상 확인 방법
근거 연결 정확도 인용한 문서의 해당 부분이 실제로 그 주장을 뒷받침하는지 확인
Claim 커버리지 사람이 중요하다고 정리한 기술 주장 중 AI가 놓치지 않고 추출한 비율 비교
방법론 체크 누락 Sample Methodology의 필수 확인 항목을 AI가 실제로 모두 점검했는지 확인
중요 쟁점 탐지 사람이 정리한 핵심 누락·불일치·추가 확인사항을 얼마나 찾아냈는지 비교
Reviewer Queue 유효성 AI가 우선 검토로 올린 항목 중 실제 사람이 확인할 가치가 있었던 항목의 비율 측정
질문의 구체성과 실행 가능성 기업의 특정 주장·문서·버전·누락 조건을 짚고, 어떤 자료를 받으면 쟁점을 해결할 수 있는지 사람이 평가
수정 부담과 자료 한계 수정·삭제한 결과 비율을 기록하고, 자료 미발견·검색 실패·접근 실패·내부자료 필요를 구분해 집계
과잉 판단 방지 자료 부족을 허위나 기술 부족으로 잘못 판정하지 않았는지 확인
실제 시간절약 자료 탐색부터 검토 완료까지 수작업과 AI 보조 방식을 비교
시간절약률 (수작업 시간 - (AI 처리 시간 + 사람의 검토·수정 시간)) / 수작업 시간
AI가 초안을 빨리 만들었다는 것만으로 시간절약이 입증되지는 않습니다. 오류를 고치고 출처를 다시 확인하는 시간까지 포함하고, 같은 검토 완료 기준을 적용해야 합니다. 동일 담당자가 같은 기업을 연속 조사하면 학습 효과가 생기므로, 담당자를 나누거나 유사 사례의 조사 방식을 교차 배정해 영향을 줄입니다.

검증 데이터셋도 공개자료만으로 구성

PRIMARY BENCHMARK

한국 공개자료 · 주 검증셋

분석 기준일과 자료 묶음을 고정하고, 사람이 AI 결과를 보기 전에 주장·근거·비교조건·쟁점·질문 기준셋을 작성합니다. 사람과 AI에 동일한 자료를 제공해 결과를 비교하며, 가능하면 기술평가 경험자가 일부 사례를 검토합니다. 사람이 놓친 유효한 발견도 원문으로 재검토해 기준셋에 반영하고 두 방식의 결과를 같은 기준으로 다시 평가합니다.

SUPPLEMENTARY SET

과거 평가의견·SEC 질의 · 보조 자료

과거 A·BBB 등급은 기업 단위 종합 결과이므로 Claim·Evidence·쟁점·질문의 정답으로 쓰지 않습니다. 공개된 종합의견과 SEC 질의는 공개자료로 확인 가능한 쟁점에 한해 보조적으로 참고합니다. 당시 탐지를 시험할 때는 기준일 이후의 답변·수정본을 입력에서 제외하고 당시 공개된 자료 버전을 확인합니다.

고정 자료 묶음의 검증은 분석 품질을 확인하는 실험입니다. 자료 탐색부터 검토 완료까지의 실험은 별도로 수행해 수집 실패와 총시간을 기록합니다.

공개된 상장 성공기업만으로 시험했다면, 상장에 이르지 못한 기업까지 일반화할 수 있는지는 별도로 검토해야 합니다.
