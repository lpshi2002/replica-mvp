# 기존 대화의 진행자 제안

출처: O3 적용 뒤 사용자 질문에 대한 현재 대화의 답변. 사용자 확정 정책이 아닌 토론 시작 제안이다.

현재 화면 읽기 → LLM 판단 → 행동 1개를 반복하므로 전달량 최적화만으로 호출 수는 줄지 않았다. 다음 핵심은 단순 조작마다 LLM을 부르는 횟수를 줄이는 것이다.

- O1: 이미 확인한 폼의 입력·선택·제출은 한 번 계획하고 코드가 순서대로 실행한다. 각 입력·화면·결과 기록은 남긴다. 새 화면·예상 밖 변화·오류에서 모델이 다시 판단하고 화면이 달라지면 남은 묶음을 멈춘다.
- O2: 대기·명확한 완료 표시 확인은 기존 코드 경로를 활용한다.
- O4: 결과의 품질·의미 평가는 기존 독립 LLM Judge를 유지한다.
- O6: 이전 결론의 캐시 재사용 실험 후보도 같이 재검토한다. 고정 지침을 옮기는 것 자체로 효과가 난다고 가정하지 않는다.
- O5/O7: 기존 선택 시험을 활용하고 동일 입력·앱·모델·범위에서 비교한다.

이번 검토에서 제한된 폼 묶음과 더 넓은 계획-코드실행 방식 중 무엇이 현재 코드에 적절한지, 실제로 호출/비용이 감소할 여지가 충분한지, 안전장치가 과도하게 복잡해지는지를 반박·구체화한다. 이전95/401은 인접 패턴 후보일 뿐 실제 절감률이 아니다.
