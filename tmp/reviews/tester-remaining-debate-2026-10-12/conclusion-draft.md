# 남은 AI 테스터 최적화 토론 결론

2026-10-12. 기존 제안 → Claude 검토 → Codex 수정 → 같은 Claude 세션 재검토를 완료했다. 설계 권고이며 구현이나 비용 절감 실측 결과가 아니다.

## 권고

**작은 캐시 유지 시간 비교를 먼저 끝낸 뒤, 한 폼의 입력과 제출을 묶어 모델 호출 수를 줄인다.** 브라우저는 사람이 쓰는 실제 화면을 검증하기 위해 유지한다. 단순 조작마다 하는 모델 판단과 반복 요청의 비용을 줄이는 방향이다.

## O8: 작게 검증하고 채택 여부를 정한다

공식 문서에서 `-p`의 `CLAUDE_CODE_PROMPT_CACHE_TTL=5m` 지원을 확인했다. 설치된 Claude Code 2.1.296은 최소 버전 조건을 충족한다. 실제 safe-mode 조합의 적용 여부와 비용 효과는 영수증으로 확인해야 한다. [공식 TTL 문서](https://code.claude.com/docs/en/prompt-caching#choose-the-ttl-yourself)

1. tester 자식 환경의 복사본에 허용된 변수만 설정한다. 부모 셸·사용자 설정·Judge·복제품 내부 모델 호출은 유지하고, 적용한 설정과 CLI 버전을 기록한다.
2. 동일한 저장 프롬프트·모델·스키마로 현재 설정과 5분을 비교한다. 순서를 뒤집은 비교까지 **최대 8호출**로 탐색한다. 첫 호출을 자동으로 cold cache라고 부르지 않는다.
3. 실제 TTL 전환, 쓰기·읽기·비캐시 입력·출력, 총비용, 시간, 구조화 출력 실패를 함께 본다. 효과가 반복되면 선택 사례에서 실제 평가 경로의 환경 전달·영수증·완료/실패 표시·증거 저장을 점검한다.
4. 설정 무효·비용 증가·출력 실패·비교 불가능이면 채택을 보류하고 O1로 넘어간다. 캐시 조사를 계속하느라 호출 축소를 미루지 않는다.

캐시 전체 끄기는 유용한 재사용도 없앨 수 있어 첫 실험에 섞지 않는다. 5분을 넘는 공백에서도 같은 효과가 난다고 일반화하지 않는다. O6의 옵션 추가나 프롬프트 이동도 별도로 비교한다.

검증 깊이에는 의견 차이가 있었다. Codex는 선택 사례의 품질 비교까지 권했고, Claude는 TTL만 바뀌므로 영수증 확인이면 충분하다고 봤다. 진행자는 순수 TTL 변경에 대해 입력·스키마·환경 격리의 로컬 검사, 소규모 호출 비교, 선택 사례 연결 점검으로 정리했다. 별도의 대규모 품질 A/B는 요구하지 않는다. 행동 자체가 바뀌는 O1에는 아래의 품질 비교를 유지한다.

## O1: 한 번 판단하고 입력과 제출을 실행한다

현재의 `입력 판단 → 전송 판단 → 응답 판단`을 `입력·전송 판단 → 응답 판단`으로 바꾼다. 응답 이후에 모델이 필요해도 입력과 제출을 묶는 호출 하나는 줄일 여지가 있다.

첫 구현은 관측한 한 폼의 fill/check/uncheck/select 중 하나와 마지막 click 하나로 제한한다. 대화의 다음 답변, 탐색, 업로드까지 미리 실행하는 범용 플래너는 첫 범위에 넣지 않는다.

- 관측 때 붙잡은 실제 DOM 노드와 폼이 실행 직전에도 같은 객체인지 확인한다. 같은 ref·레이블·URL만으로 통과시키지 않는다. 재탐색 locator가 교체된 노드를 대신 조작하지 않게 한다.
- 입력 결과·선택지·폼 소속·활성/가시 상태와 화면 변화를 확인한다. 새 필드·오류·화면 전환처럼 판단이 필요한 변화에는 남은 묶음을 멈춘다. 폼 소속을 확인할 수 없으면 단일 행동으로 진행한다.
- 원자 행동마다 입력·이벤트·화면·중간 관측을 남긴다. 중간 관측으로 ref를 재번호화하지 않는다.
- 오류·증거 저장 실패·시간/사용량/행동 상한에서 멈춘다. 실행한 앞부분과 중단 이유를 보존한다. 결과가 불명확한 제출은 자동 재클릭하지 않는다.
- 실행 전에 거절된 묶음도 tester 호출 상한에 포함한다. 초기 호출 상한은 기존 `max_actions_per_case`보다 늘리지 않고, 실행한 원자 행동의 예산도 따로 유지한다. 거절된 관측에서는 단일 행동으로 돌아가며 반복 거절 시 그 사례의 묶음을 끈다. 실행 0건인 거절이 반복돼도 종료 사유를 남기고 멈추는지 검사한다.
- 마지막 클릭 뒤에는 모델이 새 화면을 보고 다시 판단한다. 실제 기능의 성공 여부는 독립 Judge가 증거로 판정한다.

노드 교체·ref 복사·조건부 필드·선택지 변경·부분 실패·중복 제출·예산·증거 누락을 로컬 fixture에서 검사한 뒤 선택 사례 A/B를 한다. 최종 평가 범위나 실제 외부 효과의 증거 기준은 줄이지 않는다.

## 정정한 판단과 검증 기준

Claude 1차 리뷰의 427건은 Opus 242건과 Sonnet 185건으로, 최신 최종 401건과 다르다. 전체에 Sonnet 단가를 적용한 $7.15·87% 및 절감 추정은 채택 근거에서 제외한다. 일정한 cache_read 값만으로 어떤 블록이 재사용됐는지, 사용자 본문이 전혀 재사용되지 않았는지도 확정할 수 없다. 기존 95/401은 인접 패턴 후보이며 안전한 묶음 수·절감률·상한으로 쓰지 않는다. Claude 재검토의 73개 입력→클릭 후보도 같은 한계가 있다. 실제 폼·노드 검증 없이 모두 적용 가능하다고 확정하지 않는다.

추가로 최신 401개 영수증을 독립 확인했다. 모두 `num_turns=2`지만 `usage.iterations`에는 `type=message`가 하나씩 있었다. 이 결과는 두 번의 모델 요청이 낭비된다는 주장을 뒷받침하지 않는다. 네트워크 요청을 추적하지 않았으므로 전체 내부 요청 수나 캐시 블록의 정체까지 확정하지 않는다. [독립 확인](coordinator-iterations-evidence.json)

Claude가 재검토에서 제시한 Sonnet 323건의 약 34% 감소는 사용량이 변하지 않는다고 가정한 TTL 단가 산술이다. 이번 결론은 이를 예상 절감률로 채택하지 않으며, 8호출 실험에서도 확인 전에는 약속하지 않는다.

기존 CLI 정가 추정액은 원자료로 보존한다. 공식 가격 환산은 모델·가격표 날짜·TTL을 명시해 별도로 표시한다. 실제 청구액과 구독 한도 소진 효과는 아직 미측정이다.

채택에는 같은 앱·사례·입력·모델·예산·기대조건에서 **실패와 폴백을 포함한 총비용 감소**, 완료율·미평가·알려진 실패 탐지·증거 보존의 퇴행 없음이 함께 필요하다. 기존 Judge와 판정이 같다는 사실만으로 정확성을 입증하지 않는다. 실험군이나 비용 정보를 판정 근거로 주지 않는다.
