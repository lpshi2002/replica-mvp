**B1 실행·중단 계약**

테스터가 현재 관측한 화면을 기준으로 여러 UI 행동과 예상 사후조건을 계획한다. 별도 plan/router 호출은 추가하지 않는다. 실행기는 허용된 행동을 순서대로 실행하되 아래 S1~S6을 모두 지킨다.

- **S1 — 선언된 대기:** 진행 표시와 대기 조건은 tester가 관측을 근거로 계획에 명시한다. 로컬 제한시간 내 조건이 만족되지 않으면 남은 계획을 중단하고 새 화면을 tester에게 보낸다. 코드가 화면 문구를 추측해 대기 조건을 만들지 않는다.
- **S2 — 예상 밖 변화:** 각 원자 행동 후 화면, URL, 대화상자와 오류 표시를 관측한다. 사전조건과 다른 이동·오류·새 필드가 나오면 계획을 멈춘다. 모델이 아직 처리되지 않은 결과를 받기 전에는 다음 입력을 실행하지 않는다.
- **S3 — 실제 노드 동일성:** 한 계획 안에서 재사용하는 대상은 관측 시 잡은 실제 DOM 노드와 실행 시 노드가 같은지 확인한다. 이름·role·ref가 같아도 노드가 교체됐으면 중단한다. 대상이 없거나 여러 개거나 노드 동일성을 확인할 수 없어도 중단한다.
- **S4 — 부분 실행 기록:** 실행한 원자 행동별 입력, 중간 관측, 오류, 결과 증거와 중단 지점을 기록한다. 재개 시 이미 실행된 접두부를 표시하고 같은 제출을 반복하지 않는다.
- **S5 — 제출·중복 실행 방지:** 제출성 행동은 계획에서 한 번만 실행한다. 성공 여부가 불명확하면 자동 재클릭하지 않고 새 관측을 모델에 전달한다.
- **S6 — 예산과 품질:** 모델 호출 예산과 원자 행동 예산을 별도로 관리한다. 거절된 계획, 새 판단, fallback, 재개 호출도 비용에 포함한다. 고정된 실패 fixture에서 과거에 실패한 동작이 새 방식에서는 성공으로 잘못 처리되지 않는지 검사한다. 기존 Judge와 답이 같은지만으로 품질을 인정하지 않는다.

원자 행동별 기록은 유지한다. 따라서 B1의 기대효과는 **행동 이력 축약**이 아니라 **행동 사이 모델 호출 기회 감소**다. 의미적 결과의 Judge는 별도 역할로 계속 실행한다.

**B2 선택지와 보류 조건**

좁은 후보는 첫 실제 사례에서 이미 실행된 UI 절차를 기록하고, **동일 평가의 후속 사례**에서 반복되는 화면 구간에만 적용하는 것이다. 별도의 탐색 사례나 절차 선택용 LLM은 추가하지 않는다. 기존 tester 호출에 제한된 후보 정보를 제공하거나, 확정된 일치 규칙으로 후보를 연결한다. 어느 쪽이든 후보 선택에 드는 추가 문맥 비용을 잰다.

재사용해도 현재 사례의 화면을 다시 관측하고 대상 노드·입력값·선택지·사전조건을 확인한다. 모든 행동 뒤 새 화면 증거를 저장한다. 조건부 필드, 새 응답의 의미를 읽어야 하는 단계, 노드 교체, 절차 불일치에서는 재사용을 멈추고 B1의 일반 판단 경로로 돌아간다. 절차는 사례 입력이나 결과 판정을 저장하지 않는다.

첫 평가에서 반복 절차가 얼마나 나오는지, 계획 출력이 몇 토큰 늘어나는지, 절차 검증과 fallback이 얼마나 발생하는지에 대한 근거는 아직 없다. 그러므로 재사용 효과가 작거나 크다고 단정할 수 없다. B1 측정 후 다음 항목을 비교할 수 있을 때만 채택한다.

`재사용으로 줄어든 tester 호출의 실제 비용 > 첫 사례의 절차 기록·검증 비용 + 추가 문맥·계획 출력 비용 + 카탈로그 비용 + fallback·복구 비용`

비용이 줄더라도 완료율이나 실패 탐지가 나빠지면 채택하지 않는다. 사례 간 결과 판정은 재사용하지 않는다.
