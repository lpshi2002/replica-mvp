## 작업 2(1a·1b·1c) 세부

- **1a 입력 소진과 재시도 안내.** 
  - 재시도 피드백 `note`(`web_evaluation.py:144`)가 상태와 무관하게 "이 이유가 설명하는 동작을 고쳐라"로 고정돼 있다. 판정만 바꾸면 유인이 남으므로 함께 고친다. 입력 부족만 남으면 구현 재시도를 요구하지 않고, 다른 실패가 함께 있으면 그 실패만 전달한다. 입력 부족에는 "공개 규칙을 바꿔 해결하지 말 것"을 명시한다.
  - 입력 소진 미평가는 **실행 입력 자료 구간 → 실제 입력 사건 → 제출·이후 관측**의 대응 근거가 있을 때만 인정한다. 코드는 참조한 자료·사건의 존재, 실행 여부, 오류·취소 여부를 확인하고, 판정자는 "자료 부족"과 "충분한 자료를 앱이 처리 못 함"을 구분한다. 근거가 없으면 예외를 적용하지 않는다. 충분한 입력으로도 결과 조건에 미달하면 실패다.
  - 1차 방지책은 2차 지침의 도달 가능한 입력·짝 시험이고 1a는 안전망이다.
- **1b 의미 약화 코드 검사.** 지적 유형 `semantic_weakening` 하나 추가(위반 규칙, 코드 위치, 수락·진행·거부 조건 변화 요구). 검사 입력에 고정 공개 규칙 인용·해석·기대 결과, `our_condition`, 직전 제출 대비 변경 파일 차이(삭제 포함), 이번 개발 기록을 추가. 이전 번들은 이미 `single_agent.py:247-257`이 보관하므로 개발 로그 사본만 추가. 추가 이력 전체 상한(초기 200,000바이트), 상한 초과로 관련 로직을 못 보면 통과 불가. `evaluator_version`(`web_checkpoint.py:14`)에 `web_evaluation.py` 추가, 검사 입력 해시를 재사용 조건에 연결. 정상 개선·내부 점수 변경 자체는 금지하지 않는다.
- **1c 숫자 거부 검사.** `public_rule` 기대 결과·해석의 수치 조건(횟수·시간·비율 한도)이 인용에 없으면 고정 전 거부. 해석 못 한 표기는 통과로 보지 않는다. 자동으로 `our_condition`으로 바꿔 통과시키지 않는다. 보장 범위는 "기록된 인용과 수치 조건의 불일치"까지다.
