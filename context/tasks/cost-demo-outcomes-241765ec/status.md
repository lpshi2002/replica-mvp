## 현재 상태
이전 토론은 Claude 재검토까지 마쳐 resolved로 종료했다. 이후 사용자 정정으로 일부 전제가 대체됐다. 새 전제에 대한 Claude 재검토나 제품 구현은 아직 하지 않았다.

## 후속 사용자 정정 — 현재 우선

- 기업 입력 이후 조사·사례 작성·구현·시험·기록·보고·체험 제공까지 완전 자동화한다. 중간 사람 개입·사람 승인 관문은 없다.
- 사람 테스트는 최종 산출물을 시각적으로 직접 써 볼 수 있다는 뜻이다. AI 테스터와 같은 복제품·사용자 작업 경로를 사용하며 사람 검토를 완료 조건으로 두지 않는다.
- 사람의 작업 시간은 기본 비용 항목에서 제외한다. 엔진 JSON만의 시험은 개발 중간 검증이며 공통 체험 경로까지 제공·시험해야 요청한 결과가 완성된다.
- 정정 원문과 이전 합의에 미치는 영향: [brief.md](brief.md), [conclusion.md](conclusion.md). 아래 쟁점 표는 이전 토론 기록이다.

## 현재 제안
공통 방향은 한 실행에서 비용·실제 AI 조작·관측 결과를 남기고 기존 자원/파일/상태 기록을 재사용하는 것이다.
003은 기존 bundle_session을 통한 다중 턴 엔진 호출과 첫 기술 검증에서 harness·운영 규칙 변경 제외를 수용했다.

## 수정안의 쟁점 처리

- CDO-07: 누락 보완 수용. noncached 값 자체가 틀렸다는 해석은 기각. 원시 usage 보존, 포함 관계 불명확 시 총량 없음. 기존 judge 교체는 후속.
- CDO-08: 조건부 수용. 절대경로·호출별 영수증·전달/중단/병렬 검증. 투명성 불확실 시 shim을 끄고 새 상태에서 재실행, 내부 비용 미측정.
- CDO-09: CLI 정가 추정액 별도 표시 수용. 과거 세션 전환 비용과 새 시연 합계 분리.
- CDO-10: 중복 위험 수용. 최신 결과 하나만으로 과거 총비용이 완전하다는 해석 기각. 새 호출 ID별 집계.
- CDO-11: 수용. 승인·거절 두 사례를 engine_json에서 실제 여러 턴 실행. 사람용 화면/실제 이메일 검증은 주장하지 않음.
- CDO-12: 공개 자료 출처 경계 수용. 과거 vault 접근 및 해시 대조는 첫 단계에서 기각(유출 검증을 보장하지 않으며 불필요한 의존).
- CDO-13: 수용. 신규 demo/계측 helper/runtime 선택적 연결/CLI/테스트로 한정. 기존 completion·봉인·harness·회사 집계·Skill 전환은 후속 통합.
- 002의 CDO-14 참조는 CDO-13 오기로 처리. 단계마다 사용자 재승인을 요구하는 관문은 채택하지 않음.

수정 근거와 미검증 조건은 003의 해당 ID를 따른다. 모델 간 합의는 사용자 승인으로 간주하지 않는다.
