# 보고서·복제품 분리에 따른 수정 결론

2026-10-15 (Asia/Seoul). [이전 토론](../experience-evidence-priority-57f0541a/conclusion.md)을 분리 전제로 재검토했다. Codex 제안 → Claude 반론 → Codex 수정 → 같은 Claude 재검토를 완료했다. 제품 코드나 기존 실행 결과를 변경한 것은 아니다.

**분리는 책임과 완료 기준, 우선순위를 바꾼다. 복제품은 보고서 없이 쓸 수 있어야 하고, 보고서는 복제품을 실행하지 않아도 판단 근거를 이해할 수 있어야 한다.** 두 산출물의 관계는 평가 대상 구현과 실행 근거로 확인한다.

## 이전 결론에서 바뀌는 것

| 항목 | 이전 제안 | 수정 권고 |
|---|---|---|

## 첫 작업과 뒤따를 일

**첫 작업은 근거 없는 새 판정을 막고 기존 보고서를 확인 가능하게 만드는 것**이다. 링크 블록만 붙이는 안은 기각했다. 보고서에 claim·계획·후보 해시가 있고 기업 앱 상태도 이미 기록되어 있어, 연결 자체의 상당 부분이 존재하기 때문이다.

- 판정이 같은 실행·사례의 보존된 근거를 가리키는지 검사한다. 행동 이벤트뿐 아니라 초기·중간·최종 화면, 파일, 결정적 검사를 참조할 수 있게 한다. 초기 화면만으로 정당한 판정이 가능한 사례를 누락하지 않는다.
- 유효 근거가 없는 새 충족·불충족 판정은 원응답과 차단 이유를 보존하고 미평가로 남긴다. 참조 무결성을 의미상 정답 보증으로 표현하지 않는다.
- report.md와 architecture.md를 연결하고 필요한 실행 식별 정보, scenario_id, 읽을 수 있는 checked_at과 제공 상태를 보완한다. 아직 평가하거나 구현하지 않은 주장에 존재하지 않는 해시·시나리오를 요구하지 않는다.
- 이전 판정·결과 파일을 소급 변경하지 않는다. 과거 근거가 부족하면 그 한계를 설명한다.

후속 작업은 두 산출물의 책임에 따라 진행한다.

1. **복제품과 평가 입력:** 고정·생성 업로드 모두 신규 평가 전에 내용을 보존하고 해시를 실행·재개 판단에 연결한다. 그 다음 공개 고정 규칙으로 생성한 새 자료를 같은 웹 화면에 넣어 실제 업무 단계를 수행한다. 해시를 붙이는 일만으로 새 자료 사용성을 검증했다고 하지 않는다.
2. **평가 대상과 체험 대상의 일치:** 평가된 동일 버전으로 제공하기 전에 bound 후보 해시와 현재 후보를 비교한다. 그 경로에서 불일치를 숨긴 채 평가된 앱으로 제공하지 않는다. 별도 버전으로 제공하는 흐름은 이번 제안에서 추가하지 않는다. 해시 일치는 외부 모델·환경·사용자 상태·결과까지 같다는 보증이 아니다.
3. **보고서의 질문·추가 실험:** 공개 주장에 빠진 조건·근거에서 나오는 질문은 앱 작업과 별도로 시작할 수 있다. 재현 관측에서 나오는 질문은 해당 근거를 확인한 후 만든다. 질문마다 무엇이 부족하고 어떤 답이나 실험이 그 공백을 줄이는지 연결한다. 생성하지 않은 질문을 ‘질문 없음’으로 표시하지 않는다. 외부 전송은 범위 밖이다.

## 각각의 완료 상태

자동 실행 종료, 보고서 생성, 보고서 내용의 완비성, 앱 제공 상태, 기능 품질을 구별한다.

- **자동 종료:** 모든 조사 주장에 실행 결과 또는 미실행·차단 사유가 남는다. 앱을 만들 수 없는 주장만 있어도 실행은 종료할 수 있다.
- **보고서:** 파일 존재만으로 완비하다고 하지 않는다. 대상 주장과 조건, 관측·판정·근거, 제외·미평가 범위, 추가 확인 사항, 적용 가능한 실행 식별 정보와 앱 제공 상태를 읽을 수 있어야 한다. 생성하지 않았거나 없는 항목은 구별한다.
- **복제품:** 로컬 실행 명령만으로 평가자가 바로 사용할 앱을 제공했다고 하지 않는다. 기동 점검은 첫 화면이 열린 기록이며 기능 품질과 구별한다. 보고서 없이도 사용법·지원 범위를 알고 자기 자료로 작업할 수 있는지가 별도 기준이다.
- **시점:** 정적 보고서는 과거 점검을 현재 서버 생존으로 표시하지 않는다. 알려진 URL에는 관측 시각과 접속 범위를 붙인다. 로컬 주소는 해당 기기에서만 접근한다. 개발자용 재실행 안내는 별도로 둔다.

사람의 직접 체험은 선택이고 자동 종료의 관문이 아니다. 새 체험 상태는 과거 평가 결과·근거·보고서를 덮어쓰지 않는다. 원제품·전문가·공개 정답 시험은 선행 조건이 아니다.

## 정정과 확인한 사실

002 Claude 검토는 과거 방향 문서를 인용해 Delphi v4를 미제공이라고 단정했다. 003에서 정정했고 004에서 Claude도 오류를 인정했다. execution-resume.md와 최신 company-claims.json은 당시 메뉴 및 claim-001 화면 HTTP200, assembled/loaded, checked_at을 기록한다. 이를 미제공으로 소급 변경하지 않는다. 이번에는 서버 접속이나 전체 업무를 다시 시험하지 않았다.

지정된 serve-company 호출 경로를 읽어 확인한 범위에서는, bound candidate_sha256와 현재 manifest 해시의 직접 대조가 없었다. 기존 작업 공간 검사는 현재 manifest와 복사된 파일/세션 표식 사이의 일관성을 확인한다. 평가된 후보와의 일치 검사와는 다르다. 향후 구현 시 이 책임 경로를 기준으로 보강한다.

## 차별화에 대한 판단

분리 후에는 복제품의 실제 사용 가치와 보고서의 판단 가치가 각각 드러나야 한다. 실험·질문 생성의 목표는 판단을 바꿀 수 있는 불확실성을 구체화하고 줄이는 것이다. 사용자에게 의미 있는 관측을 만들고, 그 근거와 한계를 설명하며, 직접 더 확인할 수 있게 연결하는 품질이 차별화 후보다. 화면 배치나 데이터 축적만으로 방어력·평가 정확성·사용자 신뢰가 입증되지는 않는다.

## 검증 범위

양측은 기존 결론·실행 기록과 관련 코드 경로를 읽었다. 진행자도 보고서 생성, 기업 앱 메뉴, 서빙, 작업 공간 검사와 최신 Delphi 기록을 대조했다. 새 테스트·앱 실행·서버 접속·기업 평가 재실행은 하지 않았다. 이전 토론의 38개 테스트 통과는 이번 검증으로 합산하지 않는다. 이번 변경은 후속 토론 문서뿐이다. 모델 간 검토 결과는 구현 승인이나 제품 구현 완료가 아니다.
