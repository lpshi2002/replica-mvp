# Codex 수정 제안: 보고서와 복제품 분리

이 제안은 사용자 결정이나 구현 완료가 아니다. 이전 결론의 앱 내부 평가 카드·근거 페이지를 첫 작업으로 삼는 순서를 수정한다. 앱은 기능 수행을, 보고서는 평가 해석과 근거를 맡는다. 연결은 기존 산출물과 실행 경로로 만든다.

## S1. 기존 I4에서 바꿀 점

- **이동:** AI 판정, 사례별 근거, 평가 한계, 추가 질문은 보고서에 둔다. 앱 안에 평가 결과 페이지를 만들지 않는다.
- **유지:** 앱은 기능의 목적, 입력·출력, 사용 방법과 지원 범위를 안내하고 실제 작업을 수행한다. AI와 사람은 같은 웹 화면과 구현을 사용한다. 사람의 직접 체험은 완료 조건이 아니다.
- **연결:** 보고서에서 해당 복제품을 열거나, 기존 실행 경로로 실행할 수 있게 한다.

이렇게 하면 앱의 실행 가능성과 평가자의 판단 근거가 서로의 완료 조건을 대신하지 않는다. 현재 앱 셸은 기업별 기능 메뉴와 `/<claim-id>/` 경로를 제공하고, 사례 보고서는 별도 `report.md`로 생성된다. 기업 결과 JSON에는 보고서·결과 경로도 기록된다. ## S2. 분리된 완료 기준

**보고서 완료:** 사람이 앱을 실행하지 않아도 읽을 수 있어야 한다. 조사된 모든 주장에 결과 상태를 남기고, 평가한 주장은 주장·사례·실행·대상 구현 버전과 연결한다. 판정 이유와 확인 가능한 근거, 평가 조건, 미평가·제외 범위를 구별한다.

**복제품 완료:** 기존 실행 경로로 웹 앱을 열어 입력을 제출하고 의도한 작업 결과를 받을 수 있어야 한다. AI 평가가 요구되는 실행에서는 AI도 같은 사용자 화면을 사용한 기록이 있어야 한다. 실제 사람의 체험은 선택이다.

두 산출물은 별도로 읽고 사용할 수 있어야 하며, 전체 전달은 둘 다 제공되고 보고서가 평가 대상 앱을 가리킬 때 완료다. 앱 실행이 불가능하면 보고서는 보존하되 앱 전달은 미완료로 표시한다. 이후 체험 상태가 과거 평가 판정이나 보고서를 덮어쓰지 않는다.

## S3. 최소 연결 정보

기존 `company-claims.json`, `report.md`, `demo-result.json`과 실행 경로를 재사용한다. 최소 연결 키는 `claim_id`, `scenario_id`, 실행 식별자 또는 `public_run_dir`, `candidate_manifest_sha256`, 계획 해시다. 보고서는 기존 결과·근거 파일과 복제품 진입 경로를 함께 표시한다.

영구 URL이 없는 실행은 새 배포 인프라를 만들지 않고 기존 `serve-company` 경로와 앱 실행 안내를 사용한다. 앱이 평가 당시 버전과 다르면 같은 평가 대상으로 표시하지 않는다. 사용자의 새 체험 상태는 평가 실행 식별자와 분리한다.

## S4. 우선순위와 첫 작업

이전 I6의 첫 작업은 근거 검증과 앱 내부 결과·체험 화면 연결을 함께 다뤘다. 분리 후에는 앱 내부 결과 화면을 제외한다. **첫 작은 변경은 기존 Markdown 보고서에 ‘복제품 열기’ 연결 블록을 추가하는 것**을 제안한다. 해당 블록에는 주장·사례·실행·manifest 식별 정보, 기존 결과·근거 경로, 앱을 여는 기존 경로를 둔다. JSON은 기존 필드로 연결할 수 없는 정보만 보완한다.

완료 조건은 보고서에서 대상 복제품과 평가 기록을 찾을 수 있고, 경로가 실패하거나 대상 버전이 다르면 그 상태를 감추지 않는 것이다. 새 대시보드·저장소·배포 체계는 필요하지 않다.

후속 순서는 다음과 같다.

1. **새 판정 전 근거 참조 검증:** 존재하지 않거나 다른 사례·실행에 속한 참조로 충족·불충족 판정을 통과시키지 않는다. 화면 관측·파일·결정적 검사 근거를 구분하고, 모두 무효면 미평가로 남긴다. 기존 판정은 수정하지 않는다. 이는 사용자 화면 작업과 별개인 평가 품질 관문이다.
2. **보고서에 질문 초안 연결:** 검증된 주장 공백, 실패·중단, 미평가 사유에 출처를 붙여 질문 초안을 만든다. 외부 발송은 포함하지 않는다.
3. **새 입력을 활용한 평가 전 업로드 검증:** 공개 규칙으로 만든 실제 파일 내용과 해시를 실행·재개 기록에 연결한다. 새 자료 검증 전에는 기존 합성 입력 결과를 일반 입력으로 확대 해석하지 않는다.

이 순서는 새 평가를 곧바로 시작해도 된다는 뜻이 아니다. 근거 참조 검증은 새 AI 판정에, 업로드 동일성 검증은 새 입력을 쓰는 평가에 앞서 완료해야 한다.

## S5. 질문 생성과 차별화

보고서가 판단 자료를 맡으므로 질문 생성은 앱 통합 뒤의 부가 기능으로 남길 이유가 줄었다. 근거 참조 검증을 먼저 하고, 보고서 연결 작업 뒤에 주장 조건의 공백·재현 중 막힌 지점·추가 자료 필요성을 출처와 함께 질문 초안으로 제공하는 편이 맞다. 질문은 원제품 접근 없이도 만들 수 있지만, 답이나 원제품 비교를 확보한 것으로 표현해서는 안 된다.

차별화의 근거도 데이터 축적 자체가 아니다. 검토할 가치는 **주장 → 평가된 복제품 버전 → 실제 작업 관측 → 판정의 근거와 한계 → 다음 질문**이 확인 가능하게 이어지는가다. 이 연결만으로 평가 정확성·신뢰·경쟁 우위가 입증되지는 않는다.
