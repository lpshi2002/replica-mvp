**O8 — 지원 확인, 작은 TTL 실험을 먼저 권고**

공식 문서는 `-p` 실행을 main conversation으로 분류하며, `CLAUDE_CODE_PROMPT_CACHE_TTL=5m`을 지원한다. TTL 환경변수는 v2.1.242 이상에서 지원되므로 진행자가 확인한 설치 버전 2.1.296은 버전 조건을 충족한다. 실제 `--safe-mode` 조합에서 적용됐는지는 영수증으로 확인해야 한다. [공식 캐시 문서](https://code.claude.com/docs/en/prompt-caching#choose-the-ttl-yourself)

최소 실험은 다음과 같이 제안한다.

1. **tester의 Claude 자식 프로세스에만** TTL 환경변수를 전달한다. 부모 환경·사용자 설정 파일·Judge·복제품 내부 모델 호출은 바꾸지 않는다. 현재 `run_model_cli`는 `subprocess.run`에 별도 `env`를 전달하지 않으므로, 향후 구현에서는 복사한 자식 환경에 허용된 변수만 덧붙인다. 설정값은 영수증과 평가 설정 식별에 포함한다.
2. O3가 적용된 동일한 저장 프롬프트 두 개를 사용해 현재 설정과 5분 설정을 비교한다. 모델·CLI 버전·스키마·인증·격리 방식은 고정한다. 우선 각 조건 두 호출로 적용 여부를 확인하고, 비교가 유효하면 순서를 뒤집은 한 쌍을 추가한다. **최대 여덟 호출의 탐색 실험**으로 제한한다.
3. 1시간/5분 쓰기, 읽기, 비캐시 입력, 출력, CLI 추정액, 모델별 환산액, 시간, 구조화 출력 실패를 함께 기록한다. 첫 호출을 자동으로 cold cache라고 부르지 않는다. 기존 캐시와 실행 순서의 영향을 구별하지 못하면 절감률을 확정하지 않는다.
4. 5분 쓰기로 실제 전환되고, 순서를 바꿔도 총비용 개선이 관찰될 때만 선택 사례의 브라우저 비교로 넘어간다. 변수 무효·비용 증가·출력 실패·해석 불가능한 변동이면 채택을 보류하고 O1로 진행한다.

`DISABLE_PROMPT_CACHING=1`도 공식 지원된다. 다만 고정 접두부와 호출 내부의 유익한 읽기까지 잃을 수 있으므로 첫 비교에 섞지 않는다. TTL 실험 결과가 비활성화 비교의 필요성을 뒷받침할 때만 별도 후보로 둔다. [공식 환경변수 문서](https://code.claude.com/docs/en/env-vars)

작은 실험이 통과해도 모든 실행 간격에서 유리하다는 뜻은 아니다. 5분을 넘는 공백이 있는 운영까지 확대하려면 그 조건의 손익을 별도로 확인해야 한다.

**O1 — 제한형 유지, 안전 조건 보강, 절감 논리 정정**

“응답을 보고 다시 판단해야 하므로 fill→Send의 가치가 작다”는 반론은 그대로 수용하지 않는다. 기존의 **입력 판단 → 전송 판단 → 응답 판단**을 **입력·전송 판단 → 응답 판단**으로 바꾸면 성공한 묶음마다 tester 호출 하나를 줄일 수 있다. 응답 이후 판단은 그대로 남는다.

다만 95/401은 인접 패턴 수다. 안전한 묶음 수·호출 절감률·효과 상한으로 사용하지 않는다.

첫 구현은 **이미 관측한 한 폼에서 입력 행동 하나와 마지막 click 하나, 최대 두 행동**으로 좁힐 것을 제안한다. 입력은 기존 `fill/check/uncheck/select` 중 하나다. 이 범위에서 효과가 없으면 곧바로 범용 플래너로 확대하지 않는다.

필수 실행 조건은 다음과 같다.

- 모델 호출 전 관측 시 실제 대상 노드와 폼을 붙잡고, 실행 직전에도 같은 객체이며 연결돼 있는지 확인한다. ref 문자열이나 tag/type/label 일치만으로 통과시키지 않는다. 폼 소속을 확인할 수 없는 화면은 기존 단일 행동을 사용한다.
- 다음 행동 전까지 레이블·선택지의 값과 표시·활성 상태·가시성·폼 소속을 대조한다. 입력 후 실제 값·checked·선택 결과도 확인한다. 새 필드·오류·안내·화면 전환처럼 판단이 필요한 변화가 있으면 중단한다.
- 기존 `_OBSERVE_SCRIPT`는 ref를 재부여하므로 묶음 중간에 그대로 호출하지 않는다. 번호를 바꾸지 않는 중간 관측을 사용하고, 원자 행동마다 이벤트·화면·실제 입력·관측을 연결한다. 증거 저장 실패도 남은 묶음을 중단한다.
- 재탐색 locator가 교체된 노드를 대신 조작하지 않도록 한다. 실제 노드를 대상으로 조작하고 분리되면 실패 처리한다.
- 제출 결과가 불명확하면 자동 재클릭하지 않는다. 실행한 앞부분과 중단 이유를 보존하고 새 관측으로 돌아간다. 마지막 click 뒤에는 반드시 모델이 응답을 판단한다.
- 행동·시간·사용량 예산은 원자 행동마다 확인한다. 부분 실패를 이유로 이미 실행한 입력부터 묶음 전체를 재생하지 않는다.

이는 [이전 결론](/Users/cho/replica-mvp/context/tasks/tester-cost-optimization-1be6cda7/conclusion.md)의 안전 조건을 유지하면서 첫 구현 규모를 줄인 안이다. 현재 `_perform`의 ref locator와 `_run_case`의 한 호출·한 행동 연결을 실제로 바꿔야 하므로, 단순 배열 추가로 끝나는 변경은 아니다. [현재 코드](/Users/cho/replica-mvp/src/replica_mvp/web_demo.py:379)
