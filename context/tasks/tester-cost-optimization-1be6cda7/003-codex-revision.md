**수정 결론: 첫 구현은 O3의 이력 표현 축소로 한정한다. O1 범용 batching은 후순위로 보류하고, O2·O5는 신규 구현에서 제외한다. O4 확대와 O6 캐시 이동은 검증 조건으로 남긴다.** O7은 효과를 비교할 때 적용할 측정 규칙으로 수용한다.

판단 기준은 실제 웹 화면 조작, 행동별 증거, 별도 의미 판정, 최종 전체 평가를 보존하면서 구현 복잡성과 비용을 함께 줄이는 것이다. 아래 내용은 구현 권고이며 사용자 승인이나 절감 실측 결과가 아니다.

**O1 — 후순위 반론 수용, 단순한 안전 판정은 기각**

진행자의 [입력 인접 집계](/Users/cho/replica-mvp/context/tasks/tester-cost-optimization-1be6cda7/coordinator-adjacency-evidence.json)는 상한 3개에서 21호출, 5개에서 22호출을 후보로 센다. 401호출 대비 약 5.2%, 5.5%다. 상한을 늘려 얻는 후보는 한 호출뿐이므로, 입력 묶음을 위해 처음부터 5개 배열과 범용 실행기를 만드는 우선순위는 낮다.

[마지막 버튼 포함 집계](/Users/cho/replica-mvp/context/tasks/tester-cost-optimization-1be6cda7/coordinator-terminal-click-evidence.json)의 95호출·23.7%는 검토할 가치가 있다. 그러나 같은 폼인지, 입력 후에도 버튼의 의미가 같은지, 중간 판단이 필요 없는지는 확인하지 않았다. **세 수치 모두 인접 패턴 후보이며 안전한 절감 상한이나 비용 절감률이 아니다.** Claude의 “10~30% 절감 상한이 측정됐다”는 표현은 기각한다.

안전 설계에 대한 판단은 다음과 같다.

- **수용:** 오류·화면 전환 뒤 남은 행동 폐기, 효과가 불명확한 제출 자동 재실행 금지, 원자 행동별 예산·이벤트·스크린샷 유지.
- **기각:** 재번호를 생략하고 `count()==1`이면 같은 요소라는 판단. 동일 ref를 복사한 새 노드도 이 조건을 통과한다.
- **기각:** 보이는 요소 개수가 같으면 계속 진행하는 판단. 같은 개수로 노드·레이블·선택지가 바뀔 수 있다.
- **기각:** 제출 직전 관측 하나만 추가해 중간 증거 보존을 충족한다는 안. 입력 사이에 나타났다가 사라지는 메시지를 놓칠 수 있다.

현재 [관측 코드](/Users/cho/replica-mvp/src/replica_mvp/web_demo.py:91)는 ref를 매번 재부여하고, `_perform`은 그 속성으로 locator를 다시 찾는다. 단순히 배열을 순회하면 안전성이 확보되지 않는다.

재검토할 경우 최소 범위는 **이미 관측한 한 폼의 입력과 마지막 버튼 한 번**으로 제한한다. 탐색·업로드·키 입력·대화의 다음 답변까지 묶지 않는다. 상한 3 또는 5는 아직 확정하지 않는다.

구현 착수 조건은 실제 노드 동일성, 폼 소속, 레이블·선택지·가시성 변화와 입력 사후조건을 확인할 수 있다는 것이다. 확인이 어려운 화면에서는 단일 행동으로 돌아간다. 범용 locator 복구 엔진은 만들지 않는다.

묶음 안에서도 재번호 없는 중간 관측을 각 행동에 연결하고, 마지막 클릭 뒤에는 새 관측으로 모델이 다시 판단해야 한다. 시간·사용량 한도도 원자 행동 사이에 확인하며, 실행된 접두부와 중단 이유만 기록한다. 부분 성공을 묶음 완료로 처리하지 않는다.

**O2 — 별도 작업 제외 수용**

[현재 실행 코드](/Users/cho/replica-mvp/src/replica_mvp/web_demo.py:364)에 `set_checked`, `fill`, `_wait_on_screen`, `_settle`이 있다. 기존 대기 기능을 새 절감안으로 계산하지 않는다.

다만 기존 자동대기가 O1의 모든 사후조건을 보장한다는 해석은 기각한다. 예를 들어 앱이 입력 직후 값을 다시 바꾸거나 버튼의 의미를 바꾸는 상황은 별도 확인이 필요하다. 이는 O1을 구현할 때 함께 해결할 조건이며 독립 작업으로 확대하지 않는다.

**O3 — 이력부터 줄이는 안 수용, 실제 행동값 절단 기각**

현재 [_tester_prompt](/Users/cho/replica-mvp/src/replica_mvp/web_demo.py:272)는 최근 15개 이력을 그대로 전달한다. [_run_case](/Users/cho/replica-mvp/src/replica_mvp/web_demo.py:494)는 실제 행동의 `value`와 이유를 이력에 저장한다.

첫 변경은 **원본 이력과 증거를 그대로 두고 tester 전송용 표현만 만드는 것**이다.

- 최근 15개라는 개수와 순서를 유지한다.
- `index`, 행동, 실제 `value`, 요소 구별에 필요한 정보, 오류를 보존한다.
- 성공 행동의 장황한 `reason`만 짧게 제한하고, 생략됐음을 표시한다. 오류와 중단 이유는 축약하지 않는다.
- 불필요한 JSON 공백과 빈 선택 필드를 줄인다. 효과가 작은 재구조화는 추가하지 않는다.
- 현재 화면, 사례·사실, 남은 행동 예산, `read_result`는 이번 변경에서 유지한다.

Claude의 `value` 200자 절단은 기각한다. 화면 관측의 200자 제한과 과거 실제 입력값 제한은 다르다. 현행 `read`는 **현재 필드**를 읽으므로, 사라진 긴 정정문을 과거 기록에서 복원해 주지 못한다. 이유 80자도 검증 전에는 확정 정책으로 삼지 않는다.

검증은 기존 이력 표본과 합성 장문 입력으로 먼저 한다. 긴 값·오류·순서가 보존되고 전송 길이가 줄어드는지 확인한다. 문자·바이트 감소는 토큰·비용 절감과 구분한다. 원본 이벤트와 Judge 입력이 이 변경 때문에 달라져서는 안 된다.

**O4 — 확대 보류 수용, 재검토 조건의 과도한 제한 기각**

기존 `CHECK_TYPES`와 `freeze_demo_plan`이 검사 정의·동결을 지원한다. [_evaluate_case](/Users/cho/replica-mvp/src/replica_mvp/web_demo.py:553)는 의미 조건이 남으면 사례당 Judge를 호출하므로, 일부 조건을 코드로 바꿔도 호출 하나가 바로 사라지지 않는다.

따라서 새 검사 언어·플러그인·동적 저장 구조 추론은 이번 최소 범위에서 제외한다.

다만 “모든 조건을 화면 문구로 판정할 사례가 나와야 재검토한다”는 조건은 기각한다. 일부 보조 검사도 정확성이나 Judge 입력량에 이득을 줄 수 있다. [프로젝트 방향](/Users/cho/replica-mvp/context/project-direction.md:91)도 화면 시연을 보조하는 상태·파일 검사를 허용한다.

재검토 조건은 **구현과 독립적으로 정의할 수 있고, 해당 기대 결과를 충분히 검증하는 작은 검사**가 실제로 생기는 것이다. 문구·파일 존재를 외부 발송 성공으로 바꾸지 않으며, 의미·근거 충실도 판정과 기존 동결 계약은 유지한다.

**O5 — 신규 구현 제외 수용, 과거 낭비 판정 보류**

[구현 가이드](/Users/cho/replica-mvp/docs/replica-implementation-guide.md:71)에 관련 사례 선택, 새 출력 디렉터리, 최종 전체 평가가 이미 있다. 자동 영향 분석이나 새 선택 실행 기능은 만들지 않는다.

과거 개발 시연 4건 중 3건이 전체 실행이었다는 관찰만으로 낭비나 지침 위반을 판단하지 않는다. 당시 변경 범위와 제출 준비 상태를 확인하지 않았기 때문이다.

개발에서는 구현자가 관련 사례부터 실행하고, 최종 새 후보는 전체 계약을 평가한다. [체크포인트 검증](/Users/cho/replica-mvp/src/replica_mvp/web_checkpoint.py:33)의 후보·계획·평가기·설정·증거 일치 조건을 유지하며, 새 후보에 과거 통과를 승계하지 않는다.

**O6 — 쓰기량 확인 필요성 수용, 첫 순위 채택과 14% 추정 기각**

[진행자 검증](/Users/cho/replica-mvp/context/tasks/tester-cost-optimization-1be6cda7/coordinator-verification.md)에 따르면 기록은 5분 쓰기가 아니라 1시간 쓰기 759,313토큰이다. Claude의 5분 단가 기반 84%·14% 추정은 이번 판단 근거에서 제외한다.

[모델 호출 코드](/Users/cho/replica-mvp/src/replica_mvp/model_calls.py:167)는 전체 프롬프트를 stdin으로 전달한다. 이것만으로 고정 본문이 어느 캐시 경계에 들어가는지, system으로 옮기면 재사용되는지는 확정할 수 없다.

고정 지침·행동 설명만 분리하는 안을 실험 후보로 남긴다. 사례·연구 사실·실행값·화면을 system 지시로 승격하는 안은 기각한다. 세션 격리와 사용자 모델·CLI 설정도 유지한다.

향후 검증에서는 동일 조건의 영수증으로 쓰기 감소와 읽기 증가, 총비용, 행동 품질을 함께 확인해야 한다. 기존 CLI의 기본 캐시 읽기량을 새 개선 효과로 계산하지 않는다. 현재 단계에서는 O3보다 먼저 구현하지 않는다.

**O7 — 분모 구분 수용, $10.08 전액 회피 가능 해석 기각**

$44.29는 누적 평가·등록 개발 시연 비용이고, $13.70은 채택된 최종 세 실행의 합이다. 평가기·설정 변경 뒤 재관측한 $10.08에는 필요한 검증도 포함되므로 통째로 낭비나 절감 가능 비용으로 빼지 않는다.

A/B에서는 앱 버전·사례·생성 입력·모델·예산을 고정하고 **대상 최적화만 다르게** 한다. 평가기 변경을 시험하면서 “평가기까지 동일”을 요구하는 표현은 수정한다. 양쪽 모두 새 관측을 얻는다.

정상 실행 중에는 설정을 유지하되 평가기 오류 수정이 필요하면 변경과 재관측 비용을 명시한다. [평가기 버전 계산](/Users/cho/replica-mvp/src/replica_mvp/web_checkpoint.py:14)에 포함된 파일을 수정하면 기존 증거 재사용이 제한된다는 점도 비용에 반영한다.

**최소 실행 순서와 완료 기준**

1. **O7 측정 규칙 적용:** 기존 누적 총액은 보존하고 비교 실행의 분모·변경점을 명시한다. 새 계측 시스템은 만들지 않는다.
2. **O3만 첫 변경:** 전송용 이력 축소와 장문·오류 보존을 검증한다. 기존 웹 평가 관련 검사와 저장소 테스트를 통과시킨다.
3. **효과 확인 후 다음 선택:** O6의 캐시 실험 또는 O1의 제한된 폼 묶음 중 근거가 확보된 것만 진행한다. 둘을 동시에 바꿔 효과를 섞지 않는다.

향후 구현 검증에는 `PYTHONPATH=src python -m unittest discover -s tests`, `git diff --check`, 변경·스테이징 목록 검토를 포함한다. O1을 진행한다면 같은 개수의 노드 교체, ref 복사, 조건부 필드, 선택지 변경, 부분 실패, 중복 제출, 행동 한도, 중간 증거 누락을 우선 확인한다.

실제 비교에서는 tester·Judge·전체 비용과 호출 수, 원자 행동 수, 완료·미평가, 알려진 실패 탐지를 함께 본다. 호출 감소만으로 채택하지 않는다.

이번 턴은 지정 문서·집계·관련 코드의 읽기 전용 검토만 수행했다. 파일·설정 변경, 테스트, 모델·브라우저 평가를 실행하지 않았다. **절감 효과와 O1·O6의 채택 여부는 아직 검증되지 않았다.**
