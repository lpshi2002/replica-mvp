사용자가 요청한 다섯 가지 최적화를 [Codex 기존 제안](001-codex-proposal.md) → [Claude 검토](002-claude-review.md) → [Codex 수정](003-codex-revision.md) → [같은 Claude 세션 재검토](004-claude-review.md)로 검토했다. 원래 대화의 제안을 보존해 시작했고 수정 단계에는 새 전용 Codex 세션을 사용했다. Claude는 두 검토에서 동일 전용 세션을 재사용했다.

## 첫 변경 O3의 구체적인 범위

- 원본 이벤트·화면·관측·입력값·Judge 증거는 그대로 보존한다. tester 전송용 이력 표현만 별도로 만든다.
- 최근 15개 이력의 순서, 행동 번호, 실제 입력값, 요소를 구별하는 정보, 오류·중단 사유를 유지한다.
- 성공 행동의 장황한 이유와 빈 선택 필드·불필요한 JSON 공백 등 반복 표현을 줄인다. 이유의 길이 상한은 기존 표본을 보고 정하고 생략 표시를 남긴다.
- 긴 value를 200자로 자르거나 현재 화면의 관측 한도를 더 낮추지 않는다. 현재 `read`는 과거에 입력했다 사라진 값을 복원하는 도구가 아니다.
- 현재 화면, case·facts, 남은 예산, read_result는 첫 변경에서 유지한다. 매번 별도 LLM을 불러 요약하지 않는다.

검증은 같은 저장 이력과 합성 장문·오류 표본으로 먼저 한다. 전송량이 줄고 필요한 정보가 보존되는지 확인한다. **동일한 기록 fixture를 넣었을 때** 원본 이벤트와 Judge 입력이 바뀌지 않는지 확인한다. 서로 다른 라이브 실행의 생성 출력·스크린샷이 바이트 단위로 같아야 한다는 뜻은 아니다.

## O6 캐시 실험의 경계

Actions의 개선 후 tester 영수증은 1시간 캐시 쓰기 759,313토큰, 5분 쓰기 0이다. Claude 1차 검토의 5분 캐시·잘못된 단가에 근거한 84%/14% 추정은 철회했다. [진행자 검증](coordinator-verification.md)에 공식 단가와 CLI 추정액의 차이를 남겼으며, 과거 비용 기록을 재작성하지 않았다.

고정된 테스터 지침·행동 설명만 분리하는 방식을 후보로 둔다. `--append-system-prompt` 지원은 CLI 도움말에서 확인했지만 캐시 경계와 재사용 효과는 확인하지 않았다. 연구 사실·실행값·앱 화면을 캐시 목적으로 시스템 지시로 올리지 않는다. 테스트 간 격리와 사용자 모델·CLI 설정을 보존한다.

같은 조건의 영수증에서 쓰기 감소·읽기 증가·총비용·행동 품질이 함께 개선되는지 확인한다. 기존 CLI 기본 캐시 읽기를 새로운 절감으로 세지 않는다. 문구 이동만으로 확정 절감률을 약속하지 않는다.

## O1 행동 묶음을 재검토할 조건

기존 최종 401개 행동을 읽기 전용으로 집계했다. 입력·체크·선택만 인접 묶음으로 세면 cap3에서 21회, cap5에서 22회가 후보였다. 마지막 버튼 클릭까지 포함한 cap5 패턴은 95회였다. 이는 같은 URL 안의 패턴 집계이며 같은 폼·DOM 안정성·실제 비용 절감의 검증이 아니다. [입력 묶음 집계](coordinator-adjacency-evidence.json), [마지막 버튼 포함 집계](coordinator-terminal-click-evidence.json).

배치 크기나 절감률을 이 숫자로 확정하지 않는다. 재검토하는 최소 범위는 이미 본 한 폼의 입력과 마지막 버튼 한 번이다. 탐색·업로드·키 입력·대화의 다음 답변을 범용 배열로 묶지 않는다.

필수 조건은 다음과 같다.

- 실제 노드 동일성·폼 소속·레이블·선택지·가시성·입력 결과를 확인한다. 같은 ref 한 개가 있다는 사실이나 요소 개수만으로 동일성을 판단하지 않는다.
- 각 행동에 번호 재부여 없는 중간 관측, 이벤트, 화면을 연결한다. 마지막 클릭 뒤에는 새로 관측해 모델이 판단한다.
- 예상 밖 변화·오류·시간/사용량 한도에서 남은 행동을 폐기한다. 결과가 불명확한 제출을 자동 재클릭하지 않는다.
- 원자 행동별 예산을 유지하고 실행된 접두부·중단 이유를 기록한다. 묶음 하나를 행동 하나로 세지 않는다.
- 안전하게 확인하지 못하는 화면은 단일 행동으로 돌아간다. 범용 locator 복구 엔진은 만들지 않는다.

가짜 앱에서 동일 개수의 노드 교체, ref 복사, 조건부 필드, 선택지 변경, 부분 실패, 중복 제출, 행동 상한, 중간 증거 누락을 확인한 뒤 브라우저 비교로 넘어간다.

## 비용의 분모와 평가 경계

- $44.29는 평가·등록 개발 시연의 누적액이며 tester 누적은 $31.14다.
- $13.70은 최종 채택된 세 평가의 합이며 tester는 $8.21다. 모든 개선이 동일하게 적용된 새 회사 전체 실행의 비용이 아니다.
- 같은 Actions 평가의 tester $6.80→$3.40은 한 기능의 비교다. 전체 누적 비용의 절감률로 표현하지 않는다.
- 평가기·설정 변경 뒤 재관측한 두 실행의 $10.08 전체를 낭비나 회피 가능한 비용으로 빼지 않는다. 필요한 검증도 포함돼 있다.

향후 A/B는 앱 버전·사례·생성 입력·모델·예산을 고정하고 대상 변경 하나만 다르게 한다. 양쪽에 새 관측을 얻으며 최적화에 따른 평가기 버전 차이를 기록한다. 비용·입출력 토큰·호출·원자 행동·완료/미평가·알려진 실패 탐지를 함께 비교한다. 현재 Judge 판정을 무조건 정답으로 삼지 않는다.

개발 중 관련 사례부터 검사하고, 새 최종 후보는 동결된 전체 계약을 검증한다. 같은 후보·계획·평가기·설정·검증된 증거에서만 중단 평가를 재개한다. 새 후보에 이전 통과를 옮기지 않는다. 평가기 오류를 고칠 필요가 생기면 버전 변경과 새 관측 비용을 명시한다.

O3도 `web_demo.py`를 바꾸면 평가기 해시가 달라진다. 이때 발생하는 재관측 비용은 정상 반복 실행에서의 절감 효과와 구분해 보고한다.

## 수행·검증 상태와 남은 사항

코드·실행 기록·영수증 읽기, 무모델 인접 행동 집계, CLI 도움말과 공식 가격 문서 확인만 수행했다. 제품 코드·복제품·동결 계약·설정은 수정하지 않았고 브라우저 A/B나 저장소 테스트도 실행하지 않았다. 토론 자체의 모델 호출은 별도다.

Claude 재검토에서 설계상 남은 반대 의견은 없었다. 미해결 실측 항목은 O3의 비용/품질 효과, O6의 캐시 경계·효과, O1의 안전한 실행 가능 범위다. 이는 다음 구현 작업의 검증 조건이며 모델 간 동의를 효과 입증으로 바꾸지 않는다.

실행 순서 권고: **비교 기준 명시 → O3 최소 변경과 검증 → 근거가 확보된 O6 또는 O1을 하나씩 비교.** 기존 자동대기·선택 재시험을 다시 만들거나 새 모델 공급자를 붙이지 않는다.
