# Codex 제안 — 직전 답변 보존

출처: 이 토론 직전 현재 Codex 채팅의 명시적 제안. 2026-10-14. 사용자 승인이나 이미 구현된 로드맵이 아니다.

## 제안의 중심

현재 Replica는 실제로 쓸 수 있는 앱과 AI 시험 기록을 만드는 기반이 있다. 먼저 '앱을 써보기'와 'AI가 왜 그렇게 평가했는지 확인하기'를 하나의 사용자 경험으로 연결한다. 전문가 검증, 원제품 비교, 여러 구현 대안 비교는 선행 조건으로 두지 않는다.

## 현재 기반과 공백

- 웹 앱 구현, 동일 사용자 화면의 AI 시험, 회사 메뉴와 경로별 기능 조립, 보존 상태에서의 실행이 존재한다. 새 입력 가능성은 예시 값 변경·코드 검사로 일부 확인하지만 기능별 새 문서·새 대화·연속 사용 품질이 보장된 것은 아니다.
- 행동·화면·파일·판정 이유·비용과 보고서는 존재한다. 공통 앱 메뉴에서는 이를 읽고 체험하는 흐름이 연결되지 않았다.
- 제외 기능, 부분 재현, 실패·미평가는 기록한다. 사용자 화면에서 한계를 즉시 파악하기 어렵다.
- 별도 기술평가 앱에 질문·검토 이력은 있으나 실행 관측에 따른 직접 확인 안내와 기업 질문 연결은 없다.

## I1 / I4: 체험 가능한 결과 제공

공통 기업 앱의 각 기능에 '할 수 있는 일 / AI가 확인한 것 / 근거 보기 / 알려진 한계 / 직접 사용'을 붙인다. 원시 파일 경로를 사용자에게 찾게 하지 않는다. 예시 또는 자기 자료로 시작할 수 있게 하고, 새 체험은 기존 평가 기록을 보존한 별도 상태에서 시작한다. 별도 평가 앱 전체 통합보다 현재 기업 앱의 작은 연결을 우선한다.

HTTP 200이나 첫 화면 로드만으로 사용 가능하다고 단정하지 않는다. 처음 보는 사람이 할 수 있는 일을 이해하고, AI 근거를 확인하고, 자기 입력으로 전체 작업을 수행할 수 있는 것이 목표다. 이 목표를 사람의 필수 참여 조건으로 바꾸지 않는다.

## I2: 기능 범위와 평가 가능성

구현 가능+AI 시험 가능이면 구현·평가한다. 구현 가능하지만 AI 시험이 어려우면 기능은 제공하고 AI 미평가로 남겨 사람이 선택적으로 체험한다. 자원·접근·기술 제약으로 구현하지 못하면 제외 사유와 필요한 조건을 밝힌다.

Delphi 제외 사유 중 고정시험 또는 테스터 제약이 언급된 부분은 실제 구현 제약과 나눠 재검토한다. 모든 제외 기능을 복구하자는 것은 아니다. AI가 시험하기 편한 범위를 제품 범위로 자동 대체하지 않는다.

## I3: 관측과 판정 연결

진행자는 직전 대화에서 _evaluate_case에 존재하지 않는 evidence_event_ids로 passed를 반환하는 stub 판정자를 넣어 실행했다. 결과는 passed를 유지하면서 evidence_event_ids가 빈 배열이 됐다. 실제 모델 판정 오류를 관측했다는 뜻이 아니라 참조 검증 누락을 확인한 것이다.

충족·불충족 판정은 유효한 화면 또는 파일 근거를 요구하고 없으면 미평가 또는 판정 재요청으로 처리한다. 업로드 파일 내용을 고정하며 체험 앱의 구현 버전과 평가 버전을 연결한다. 프로그램 검사와 AI 해석을 구분한다. 해시가 의미상 정확성을 증명하지는 않는다.

## I5: 후속 안내와 질문

실제 관측에서 (a) 자기 자료/다른 조건/저장 후 재접속 등 직접 확인할 지점, (b) AI가 확인하지 못한 부분, (c) 원제품 결과나 추가 자료가 있어야 답할 기업 질문을 만든다. 복제품으로 확인할 수 있는 것을 모두 기업 질문으로 넘기거나 체험으로 알 수 없는 것을 사용자에게 판단 가능하다고 안내하지 않는다.

## I6: 권고 순서

1. 근거 없는 판정 차단, 기능 제외 사유 재검토.
2. 기업 앱에 평가·한계·근거·체험 진입점 연결.
3. 새 입력과 연속 사용 점검 강화.
4. 실행 결과 기반 체험 안내·후속 질문 생성.

이 순서의 과도함/누락/상호의존성을 검토해 달라. 코드 수정은 요청하지 않았다.

## 직전 확인 범위

- 직전 분석에서 관련 기존 테스트 54개 통과. 이번 토론에서 다시 실행한 것은 아님.
- 최근 company-claims.json은 10개 사례/35개 조건 충족과 전체 부분 재현을 기록한다.
- 진행자는 직전 턴에 로컬 메뉴와 /claim-001/ HTTP 200을 확인했다. 새 입력을 넣어 실제 사용자 작업을 시험하지 않았다.
- 이전 context 문서의 '실제 기업으로 회사 셸 미실행' 문구는 최근 실행 산출물보다 뒤떨어질 수 있으므로 현재 코드와 해당 실행 파일을 우선 대조한다.
