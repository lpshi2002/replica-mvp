## 논의 범위

1. 1차(회사 전체 주장 발견)와 2차(주장별 심층 조사)를 나누는 것이 효과가 있는가. 약점은 무엇이고 어떻게 보완하는가.
2. 2차가 맡은 역할(조사, 경로 선택·제외 결정, 계약, JSON 시험, 봉인 평가 데이터, 시연 계획, 업로드 합성)이 과다한가. Ralph식 Inspect→Architecture처럼 조사와 설계를 나누는 것이 맞는가. 나눈다면 어떻게 나누는가(같은 조각 파일을 두 작업자가 채우기 / 파일 분리 / 다른 방식).
3. 2차가 구현 경로를 정확하게 찾지 못하는 문제의 원인과 대책. 사용자 표현대로 "여러 이유"가 있을 수 있으니 하나로 단정하지 않는다.
4. 사용자 제안: 못 하거나 애매한 단계는 건너뛰어도 되지만 무엇을 왜 못 했는지 보고서에 명시하고, 워크플로 전체의 설계도(아키텍처) 위에 직접 구현·시연 결과와 미구현 부분(하려면 무엇이 필요한지)을 표시한다. 이것을 위 구조와 어떻게 연결하는가.
