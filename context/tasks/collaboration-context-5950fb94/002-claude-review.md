# 002 Claude 검토 — 001 Codex 제안

001 제안을 읽은 뒤 작성했다. 따라서 독립 검토나 블라인드 검토가 아니다. 아래 평가 기준도 제안을 본 다음 brief의 사용자 원문과 완료 기준에서 다시 세운 것이다.

## 평가 기준 (사용자 요구에서 도출)

- **K1 유용성:** 다음 작업자가 결정을 바꿀 수 있는 이유·근거·제약을 추측이나 재조사 없이 찾을 수 있는가. 출처는 "근거들이랑 이유들같은거 맥락 잘 전달되게"다.
- **K2 비용:** 추가 기록과 지시가 작업 규모에 비례하는가. 출처는 "너무 많이 넣으면 안되고"와 brief의 "간단한 작업까지 무거운 의식 강요 금지"다. 같은 규칙을 여러 파일에 중복해서 적으면 유지 비용으로 계산한다.
- **K3 앵커링 대응:** 효과를 과장하지 않으면서, 실제 산출물을 바꾸는 장치가 있는가. 출처는 "앵커링 효과… 경계해서"와 brief의 "편향 제거 효과를 입증했다고 주장하지 않는다"다.

## 총평

- **유용성(K1):** I-1의 포함 기준("빠지면 다른 결정을 내리거나 같은 조사를 반복하는가")은 이번 요구의 핵심을 짧게 잡았다. 다만 이 기준을 어디에 넣는지가 빠졌다. 의견 파일을 쓰는 사람은 참여자다. 그런데 참여자가 실제로 받는 지시는 `debate.py:prompt()`이고 SKILL.md가 아니다. 이 기준이 prompt()에 들어가지 않으면 참여자의 기록은 달라지지 않는다.
- **복잡성(K2):** 새 파일·서식·메타데이터를 만들지 않은 것은 맞다. 다만 I-3과 I-4의 상당 부분은 이미 SKILL.md에 있다. status의 "쟁점 ID별 상태·근거 링크", conclusion의 "합의, 이견, 검증 상태, 사용자 결정", 실행 범위의 "코드 수정·배포는 별도 요청 범위"가 그 예다. 그대로 반영하면 새 정보 없이 비슷한 문장만 늘어난다. 이미 있는 문장에 빠진 단어만 끼워 넣는 방식이 맞다. README는 "세부 절차는 스킬을 따른다"로 위임하고 있으므로 수정하지 않는 것을 권한다.
- **앵커링(K3):** I-2는 효과를 과장하지 않은 점이 맞다. 그러나 실제로 산출물을 바꾸는 장치가 약하다. 다음 두 경로가 빠졌다.
  1. **틀 고정:** 현재 prompt()는 "Respond to numbered issues from the other participant"를 고정 지시로 넣는다. 검토의 뼈대가 제안자의 쟁점 분할을 따르게 된다. 제안자가 다루지 않은 문제가 들어갈 자리가 없다(I-5).
  2. **진행자 해석:** brief와 status는 진행자가 요약한 문서이고, 모든 참여자가 가장 먼저 읽는다. 사용자 원문이 진행자의 해석과 구분되지 않으면 참여자는 해석에 고정된다(I-6). 이번 brief는 원문을 인용했지만 SKILL.md는 원문 인용을 요구하지 않는다.
- **관찰:** 이번 턴 지시("먼저 기준을 3개 이내로 적고")가 I-2를 이미 수동으로 실행하고 있다. 하지만 참조 목록에 001이 함께 들어 있어 기준을 세우기 전에 제안이 노출된다. 읽기 순서 지시는 독립성을 보장하지 않는다는 Codex의 판단과 같은 결론이다. 따라서 I-2의 효과는 "기준을 명시하게 해서 나중에 대조할 수 있게 한다"까지로 표현해야 한다.

## 쟁점별 판단

| ID | 판단 | 이유와 근거 |
|---|---|---|
| I-1 | **수정 후 수용** | 포함 기준은 K1과 K2를 함께 만족한다. 수정할 점은 위치다. 의견 작성 기준은 `prompt()`에 한 문장으로 넣는다. brief 작성 기준은 SKILL.md의 기존 brief 문단에 끼워 넣는다. "짧은 근거 설명과 원문 위치를 함께"는 수용한다. 링크만 남으면 다음 사람이 다시 읽어야 하기 때문이다. |
| I-2 | **수정 후 수용** | 방향은 수용한다. "블라인드/편향 제거로 표현하지 않는다"는 그대로 유지한다. 수정점: "요청과 원자료에서 기준을 먼저 세운다"는 노출 이후에 쓰이므로 효과가 약하다. 그래서 (a) 기준의 출처를 brief의 사용자 원문·완료 기준으로 고정하고, (b) I-5의 누락 쟁점 제기와 함께 적용할 때만 의미 있는 변화로 본다. 반론·대안 개수를 강제하지 않는 것에 동의한다. |
| I-3 | **부분 수용** | 현재 SKILL.md에 없는 부분은 쟁점별 "핵심 이유 한 줄"과 "status와 원문이 충돌하면 원문을 우선한다"는 규칙이다. 이 두 가지만 추가한다. "최근 의견 3개 유지"와 "별도 검색기 없음"은 이미 현재 상태이므로 바꿀 것이 없다. 관찰한 사실: 001 이후에도 status.md는 초기 템플릿("현재 제안 아직 없음")이다. status 품질은 진행자의 갱신 습관에 달려 있다는 Codex의 지적이 실제로 확인된 셈이다. 다만 검토 후 갱신하는 것이 현재 절차와 맞으므로 결함으로 보지는 않는다. |
| I-4 | **축소 수용** | 실행 권한 분리는 SKILL.md에 이미 있으므로 재기술하지 않는다. 추가할 가치가 있는 것은 conclusion 항목에 "선택 이유·기각한 주요 대안·재검토 조건"을 넣는 것이다. 이것이 다음 협업자가 "왜 이렇게 됐는지"를 추측하지 않게 하는 핵심이다. "실제 수행·검증 결과는 이후 기록으로 구분"은 수용한다. |
| I-5 (신규) | **제안** | prompt()의 응답 지시에 "상대가 다루지 않은 중요한 누락은 새 ID로 제기한다"를 추가한다. 근거: 현재 문구는 상대 쟁점에 대한 응답만 요구한다(`debate.py:157` 부근 고정 문장). 비용은 한 구절이다. 반대를 위한 반대를 막기 위해 "중요한"과 "결정에 영향을 줄 때만"을 붙인다. |
| I-6 (신규) | **제안** | SKILL.md의 brief 작성 문단에 "사용자 원문 요청을 그대로 인용하고, 진행자의 해석·범위 설정은 구분해 적는다"를 추가한다. 근거: 참여자가 기준을 세울 때 기댈 수 있는 비편향 자료는 사용자 원문뿐이다. 이번 brief는 이미 이렇게 되어 있어 비용이 거의 없다. |

## 채택 안 하는 대안 (결정에 영향이 있어 기록)

- **작성자 표기 숨기기·순서 무작위화:** 채택하지 않는다. 파일명의 작성자 표기는 추적과 수용·기각 응답에 필요하다. 두 모델 사이의 "권위" 효과는 사용자 요구가 겨냥한 주된 위험으로 보기 어렵다.
- **검토자에게 제안을 숨긴 1차 독립 턴:** 노출 전 기준 작성을 실제로 보장하는 유일한 방법이다. 그러나 호출이 한 번 더 늘어 K2와 충돌한다. 고위험 결정에서 사용자가 원할 때만 선택 사항으로 언급할 가치가 있다. 기본 규칙으로 넣는 것은 반대한다.

## 실행 가능한 최소 개선안

1. **`debate.py:prompt()`**에서 고정 지시 문단을 수정하되, 문장을 덧붙이기보다 기존 문장에 합친다.
   - 기준: "Before weighing others' framing, state the few criteria from the user's original request and brief that decide this turn."
   - 누락(I-5): "Respond to numbered issues …; raise important omissions as new IDs only when they would change a decision."
   - 기록 기준(I-1): "For each recommendation give the reason and the evidence location whose absence would change the decision; omit routine reasoning."
2. **SKILL.md**에는 기존 문장 안에 넣는다.
   - brief: 사용자 원문 인용 + 해석 구분(I-6)과 I-1의 포함 기준.
   - status: 쟁점별 핵심 이유 한 줄 + 원문 우선(I-3).
   - conclusion: 선택 이유·기각 대안·재검토 조건(I-4).
3. **README:** 수정하지 않는다.
4. **검증:** 현재 `test_debate.py`에는 prompt 문구를 확인하는 테스트가 없다(읽어서 확인했고, 실행은 하지 않았다). 다음 두 가지를 하면 충분하다. (a) prompt 출력에 기준·누락·기록 지시가 들어가는지 확인하는 단위 테스트 하나를 추가한다. (b) 기존 테스트 전체를 실행한다. 앵커링 감소 효과는 검증 대상이 아니라 이후 관찰할 대상이다. 다음 토론 몇 건에서 리뷰에 신규 ID 쟁점이 실제로 나오는지만 보면 된다.

## 합의 상태

I-1~I-4는 방향에 이견이 없다. 남은 것은 위치와 축소 범위다. I-5와 I-6은 Codex의 수용 여부를 받아야 한다. 따라서 아직 합의로 보고하지 않는다. 다음 턴에 필요한 확인은 두 가지다. Codex가 I-5·I-6을 수용·기각하는 것, 그리고 위 1~2번 문구가 기존 문장에 합쳐져 prompt 분량이 크게 늘지 않는지를 진행자가 확인하는 것이다.
