**수정안은 기존 구조를 유지하되 기록 기준·근거 충돌 처리·인계 확인을 보강한다.** 아래 문구는 적용 제안이며, 사용자 결정이나 최종 합의가 아니다.

**I-1 — 수용.** 참여자가 받는 `prompt()`에 기록 기준을 넣고, SKILL.md에는 진행자의 문서 관리 책임을 둔다. 적용 문구: “결정이나 후속 실행에 영향을 주는 제안에는 핵심 이유와 근거 위치를 적는다. 빠지면 다른 결정을 내리거나 같은 조사를 반복할 정보만 보존하고, 미확인 가정은 표시한다.” 새 서식은 필요 없다. 선별 비용과 누락 가능성은 남으므로 짧은 설명에 원문 링크를 붙인다.

**I-2 — 수정 수용.** 기준을 사용자 원문·brief에만 고정하면 진행자의 완료 기준이나 사용자의 사실 가정까지 정답으로 취급할 수 있다. 적용 문구: “현재 사용자 요구·제약과 확인한 원자료에 비추어 이번 판단을 좌우하는 기준을 짧게 밝히고, 상대안의 근거와 중요한 성립 조건을 대조한다.” 기준이 같으면 매번 반복하지 않는다. 이는 판단을 대조 가능하게 만드는 조치다. 기존 노출을 없애거나 독립성을 보장하지 않는다.

**I-3 — 이유 보강은 수용, ‘원문 무조건 우선’은 기각.** 과거 의견은 후속 결정으로 바뀔 수 있다. 적용 문구: “status에는 쟁점별 현재 판단·핵심 이유·근거 링크를 둔다. 원문과 충돌하면 변경 시점, 후속 사용자 결정, 확인 근거를 추적한다. 오래된 원문이나 최신 요약이라는 이유만으로 우선하지 않는다. 해결되지 않은 중요한 충돌은 명시한다.” 이번에 읽은 status는 001을 반영하므로 002의 초기 템플릿 관찰은 현재 상태에 그대로 적용할 수 없다. 이 사례도 시점 확인의 필요성을 보여 준다.

**I-4 — 축소안을 수용하되 최소 인계 확인을 추가한다.** conclusion의 기존 항목에 선택 이유와, 결정에 영향을 준 기각 대안·재검토 조건을 통합한다. 모든 대안을 채우게 하지 않는다. 제안자와 구현자가 다르면 다음 규칙을 적용한다. “실행자는 결론과 핵심 근거를 대조하고, 오해 시 결과가 크게 달라지는 범위·제약·완료 기준을 기존 계획이나 첫 진행 메시지에 짧게 재진술한다. 중요한 불일치만 확인하고, 없으면 승인된 범위에서 진행한다.” 별도 보고서나 승인 대기는 요구하지 않는다. 비용은 짧은 대조이며, 단순 복창만으로 이해가 검증되지는 않는다. 모델 합의는 권한을 만들지 않고, 실제 실행·검증 결과는 권고와 구분한다.

**I-5 — 수용.** `prompt()`의 쟁점 응답 문장을 확장한다. “기존 ID별로 수용·기각·보류와 근거를 답하되, 결정에 영향을 주는 누락은 새 ID로 제기한다.” 제안자의 쟁점 구분 밖도 검토하게 하되 신규 쟁점이나 반론의 개수는 강제하지 않는다.

**I-6 — 구분은 수용, ‘사용자 원문만 비편향 자료’라는 근거는 기각.** 사용자 원문은 의도·권한의 근거이며 사실 주장에는 오류나 가정이 있을 수 있다. 적용 문구: “brief에는 목적·범위·권한을 이해하는 데 필요한 사용자 원문을 의미가 바뀌지 않게 인용하고 출처를 남긴다. 진행자의 해석·제안은 구분한다. 사용자 발언 속 사실 주장은 필요한 경우 별도로 확인한다.” 긴 대화 전체 복사는 피하고, 후속 변경도 출처와 함께 반영한다.

추가 호출 단계·메타데이터·독립 검토 모드는 기본으로 넣지 않는다. 현재 문제는 위 문구와 근거 추적으로 다룰 수 있으며, 추가 호출은 비용을 늘려도 공통 편향까지 제거하지 못한다. README는 기존 스킬 위임을 유지한다.

수정된 I-2·I-3·I-4·I-6의 상호 검토가 남았다. 채택 후 진행자는 양쪽 호출문에 지시가 반영되는지와 기존 테스트를 확인하면 된다. 신규 ID의 수를 편향 감소 지표로 삼지는 않는다. 이번 턴에는 문서만 읽었고 수정·테스트는 하지 않았다.
