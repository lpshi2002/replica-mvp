# 현재 대화의 Codex 제안 보존

출처: 사용자가 이번 토론을 요청하기 직전 진행자의 답변. 아래는 그 명시적 제안의 요약이며 구현 완료가 아니다.

기존 기업 앱·AI 브라우저 시험·제외 범위 기록·개발 로그·누적 비용 집계를 재사용한다. 실제 코드 변경은 세 묶음으로 좁힌다.

1. 기존 _evaluate_case는 무효 근거 ID를 지워도 성공 판정을 유지할 수 있다. 화면·행동·파일 검사를 식별·보존하고 판정 참조를 검증한다. 유효 근거가 없으면 미평가로 남기고 초기 화면·파일 검사만으로 확인한 정당한 결과를 보존한다. 가짜 참조 성공 차단이 완료 기준이다.
2. _serve_company 실행 경로에서 저장된 candidate_sha256와 현재 구현 묶음을 대조한다. 기존 작업 공간·파일 검사와 체험 상태 분리는 재사용한다. 평가 뒤 바뀐 구현을 같은 평가 대상 앱으로 제공하지 않으며 새 상태 디렉터리도 검사를 우회하지 못해야 한다.
3. _instance_case는 질문·사실·기대 문구를 바꾸지만 업로드는 그대로다. 구현 전에 고정한 규칙에 따라 새 값 생성→실제 파일 생성→기존 브라우저 업로드 시험으로 확장한다. 지원 문서/CSV 작업 하나부터 완성하고 질문·파일·검사값을 일치시킨다. 사용 파일과 해시를 보존하며 재개 시 달라진 입력에 과거 결과를 재사용하지 않는다.

제외 기능은 기존 excluded_parts/alternatives/needs 자료로 구현 제약과 시험 제약을 재검토한다. 새 기록 체계를 만드는 일이 아니다. 개발 순서는 1·2의 결함 수정 후 3의 파일 변형 시험이다. 비용·시간·개발 이력은 기존 집계 활용, 보고서·질문 생성은 보류한다.
